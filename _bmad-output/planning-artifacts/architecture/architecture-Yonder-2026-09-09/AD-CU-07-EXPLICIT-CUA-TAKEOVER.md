# AD-CU-07 CUA 显式人工接管与控制提示

状态：Accepted；日期：2026-09-28。Architecture Impact：architecture-change（CUA 停止触发、桌面控制提示与宿主协调）；关联 CU-S2、TM-S3、DS-S2、AD-CU-05、AD-TM-08、AD-CX-01。

## 决定

用户明确修改此前“检测到普通键鼠输入即暂停”的行为。CUA 执行期间，普通鼠标、键盘和滚轮事件不再终止 Worker、不再生成 `unknown/user-input`，也不改变任务状态；Yonder 不拦截或吞掉这些输入。用户必须点击 Yonder 可信本机窗口中的“接管电脑”按钮，才能登记人工接管意图。系统安全界面、敏感操作确认、超时、崩溃和 Observe 失败仍按既有安全语义停止或保持 unknown。

CUA 请求进入真实执行区间时，宿主显示“Yonder 正在控制您的电脑”的常驻置顶控制条。控制条与圈选工具条复用同一显示器选择规则、工作区坐标系和顶部居中锚点（距工作区顶部 16 逻辑像素），并使用同一深色半透明圆角视觉；窗口只覆盖控制条，不建立全屏输入层。控制条展示已验证计划片段的有界步骤清单、当前正在执行的步骤摘要与唯一主操作“接管电脑”，支持键盘焦点和减少动态效果。控制条生命周期绑定已经取得 Desktop 租约并开始 CUA 的任务，而不是某一次 `computer.step`/`plan.execute` RPC；动作返回和步骤间 Observe 不得隐藏。只有该任务完成、失败、取消、显式接管成功或宿主确认执行会话终止后才清理；非 CUA、排队中或仅有任务 `running` 状态不得显示。

显式接管使用独立于任务存储锁的轻量内存信号。按钮只允许打包的 `cua-control` 窗口调用，且必须匹配宿主当前公布的 `task_id`；UI 不提交 sequence、Agent 身份、PID、窗口号或停止结果。点击后立即把卡片改为“正在安全停止”，冻结同一任务后续 CUA 派发；已交付动作不得因点击被杀死，仍须等待动作返回并完成后置 Observe。可信窗口命令必须立即把停止处理排入同一个 `TaskHost` 串行边界：动作执行中时等待其返回与 Observe，步骤间或慢脑等待期间则立即取得边界；不得依赖下一条 Agent/Gateway 请求来唤醒或消费接管信号。命令在边界内读取最新 sequence，复用 `user_takeover` 控制事务和 WorkRef 定位；Gateway/Application 在每次新 CUA 派发前只读该信号并拒绝越过。信号只由窗口命令消费，避免 UI 与 Gateway 双重提交。只有停止事务提交成功才能释放执行占用并显示已接管；结果未知时保持占用和明确失败，不自动重试。

本信号只存在于单实例进程内，不持久化，也不是第二套任务状态。宿主崩溃仍按既有 running→interrupted 恢复。历史 `user-input` 原因保留兼容读取，但新 CUA 执行不得产生该原因。

步骤展示是宿主从已验证计划片段和当前 prepared attempt 派生的只读内存投影：计划只显示步骤标签及有界序号，执行态只在真实 Driver 派发前更新；不得显示动作参数、输入正文、截图、AX 树、Agent Payload 或从 UI 反写步骤。单步 CUA 没有计划片段时仅显示当前步骤和“未提供后续计划”，不得编造步骤。投影丢失、卡片重建或宿主重启时从任务事实源重新取得，无法读取时明确显示“步骤信息暂不可用”，不能阻断或改变 CUA 执行。

## 替代关系

本决定覆盖 ARCHITECTURE-SPINE、AD-CU-05 与 AD-TM-08 中“普通输入/HID 自动暂停或终止”的旧条款；唯一 Desktop 租约、每步 Observe、未知副作用不重试和显式接管后的定位约束不变。AD-CX-01 的圈选入口改为先要求用户通过控制卡显式接管；圈选不得借普通输入自动暂停正在执行的 CUA。

## 验收

- 普通物理键鼠输入不会杀死 Worker、追加 `user-input` 结果或改变任务状态。
- CUA 执行时，当前屏幕工作区顶部居中显示控制条；位置与样式和圈选工具条保持一致，其他屏幕区域可继续交互。
- 控制条在有计划片段时展示当前执行步骤与至多四条计划步骤；已完成、执行中和待执行状态可辨，超过部分只显示数量，不展示敏感动作参数或正文。
- 只有控制卡按钮能登记本轮接管；错误窗口、错误任务和无活动 CUA 均拒绝。
- 执行中点击立即显示“正在安全停止”，当前动作完成并 Observe 后任务进入 paused、停止事实和 Outbox 原子提交、工作定位沿既有链路执行。
- 在动作执行中或步骤/慢脑间隙点击都必须收敛；后者无需等待新的 Agent 请求，刷新投影也不得重新启用已提交的按钮。
- CUA 任务完成、失败、取消、显式接管或执行会话终止后卡片必定隐藏；单个动作返回和步骤间 Observe 后仍持续显示。macOS 提供原生窗口与真实动作证据，Windows 按既有决定暂缓。
