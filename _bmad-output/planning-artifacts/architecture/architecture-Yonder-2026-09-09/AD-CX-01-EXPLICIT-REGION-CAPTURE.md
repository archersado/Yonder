# AD-CX-01 显式屏幕区域捕获

状态：Accepted（macOS既有子范围；Windows 96/192 DPI Preview）
日期：2026-09-18  
关联：CX-S2、VI-S1、AG-S5、CU-S2、AD-VI-02

## 决策问题

Yonder如何支持用户在Windows/macOS当前屏幕上圈选一块区域并交给已连接Agent，同时不变成常驻全屏应用、不持续监听输入，且不绕过CUA前台租约和隐私边界。

## 候选决策

产品名称为“圈选提问”。用户显式开始后，Desktop只在当前显示器建立一个短生命选择层；Application拥有单个圈选会话、取消/超时和临时附件生命周期。选择层不是常驻应用形态，未启动时不存在全局鼠标钩子、屏幕截图或输入记录。

平台Adapter只提供显示器快照、逻辑坐标与物理像素换算、指定区域截图及能力/权限错误。macOS候选为ScreenCaptureKit与CoreGraphics显示信息，Windows候选为Windows Graphics Capture与Per-Monitor DPI。Adapter不调用语音、Gateway、任务存储或CUA Adapter。

截图和问题在确认前仅位于有界内存或权限为当前用户的受控临时文件；取消、超时、发送确认或进程终止后清理。日志、任务事件、Outbox和普通上下文索引不保存截图、问题正文或像素摘要。密码框、系统安全界面、用户排除应用和受保护内容拒绝捕获。

用户确认“发送”后才通过AD-VI-02定义的已绑定`AgentSession`提交文字与临时附件引用。Yonder不回答、不规划、不伪造Agent身份创建任务；Agent接收后使用既有`task.create`。提交超时或断连为unknown，不自动重试。

开始圈选前检查CUA前台租约；如Agent正在控制桌面，先沿既有用户输入停止语义暂停，不与Agent争抢指针。

## Spike与淘汰门槛

统一样本用无敏感内容的本地检查图形，验证主屏/副屏、高DPI、负坐标、逻辑矩形到物理像素的一致性、Esc/超时/显示器变化清场和权限拒绝。证据只保存坐标、尺寸、色块校验与错误分类，不保存桌面截图。

任一平台无法稳定完成像素换算、取消后恢复鼠标操作，或必须常驻全局钩子才能工作，则候选路线淘汰。在双平台统一样本通过前，不新增产品Port、Gateway能力或默认权限请求。

## 2026-11-03 Windows 100%缩放Preview接线决定

Windows统一样本采用`GraphicsCaptureItem`的`CreateForMonitor`、free-threaded frame pool与D3D11 staging texture，只捕获用户显式圈选所在显示器，再以完整显示器物理原点裁剪。探针在一块96 DPI、负Y坐标副屏上连续三次通过240×160像素尺寸和四色校验；像素未落盘，进程与窗口均清理。另一块主屏真实为192 DPI，按门禁返回`capture-unsupported-scale`，未宣称通过。

据用户2026-11-03确认，接受受限Windows Preview：仅目标显示器有效DPI为96（100%缩放）、选区完全位于该显示器且像素数不超过既有限额时启用截图。其他缩放、跨屏、受保护内容、设备失败或超时必须进入无图`reviewing`，允许文字/语音提问，不得返回错位或伪截图。125%/150%/200%须取得真实统一样本后另行扩围。

该决定复用现有PreviewSession、AD-CX-02临时附件与Agent输入路径，不新增协议、持久化、默认权限请求、全局监听或第二状态所有者。Windows应用切换、显示器变化、来源应用和物理断开证据仍是后续门禁，完整CX-S2保持`verifying`。

## 2026-11-04 Windows 200%缩放Preview扩围决定

用户要求解决192 DPI（200%）主屏圈选后无图片。独立C++ WGC统一样本在该真实主屏连续三次把240×160逻辑检查窗口捕获为480×320物理像素，四色、DisplayConfig、资源释放与不落盘均通过。该证据解除192 DPI技术门禁，不替代产品共享Rust模块和确认卡验证。

Windows Preview扩围为仅接受同轴96/96或192/192 DPI。Desktop仍把CSS viewport选区按窗口物理work area换算一次，再以`rcMonitor`物理原点裁剪；不得再次乘缩放因子。120/144/168 DPI、异轴DPI、跨屏、超限或捕获失败继续进入无图`reviewing`，不返回旧图或伪图。像素/附件上限、临时内存、失败清场、协议和状态所有者均不变。

本决定不宣称完整高DPI、多显示器、应用切换、来源应用、受保护内容、权限撤销、真实显示模式变化或物理断开通过；完整CX-S2继续保持`verifying`。

## macOS子范围证据

2026-09-18单显示器、已授权样本PASS：短生命无边框四色窗口的240×161点WindowServer框稳定捕获为480×322像素，四个色块和2倍缩放校验连续三次通过。像素未落盘，无进程或二进制残留。全新临时bundle的未授权预检也连续两次失败关闭，没有请求权限或尝试截图。合成AppKit Esc/超时清场及CGHID按下-拖动-松开选区均连续三次通过，不安装全局监听、不抢前台并恢复鼠标位置。本机无副屏/负坐标；运行中撤权、显示器变化、物理键盘/鼠标及Windows仍未验证。

## 2026-09-18 macOS Preview 接线决定

用户要求先在 macOS 测试“圈选提问”。据已有单显示器、权限拒绝与清场证据，接受一个受限 Preview：仅当前显示器、显式入口、短生命选择层、临时内存截图、Esc/取消清理和确认卡。Preview 不持久化截图或问题、不自动向 Agent 提交、不在无 AgentSession 时伪造送达，也不支持副屏、跨显示器、运行中撤权或 Windows。

提交到 Agent、原始截图文件、跨显示器和 Windows 必须在各自统一样本、AG-S5 确认通道与后续 Change 通过后另行启用。此决定不授权常驻指针模式或 Record/Replay。

## 2026-09-20 CUA暂停接线定稿

macOS圈选入口复用Accepted AD-TM-08的普通用户输入停止语义。可信Desktop宿主从唯一`Admission`取得当前持有`Resource::Desktop`的任务标识，在同一宿主串行化边界内读取SQLite当前任务与attempt，提交`ControlKind::Pause`。若attempt已经普通stopped则控制事务直接暂停；若动作已返回且Observe有效但尚未推进，宿主在同一临界区确认步骤边界停止。只有paused事实、事件与Outbox提交成功并释放桌面租约后才能创建选择层。

该入口不使用takeover，不定位窗口、不启动Recording、不设置桌面接管闸。prepared、unknown、身份/序号冲突、存储失败或租约所有者缺失均失败关闭并保持选择层隐藏；不得轮询SQLite等待停止、不得仅因窗口隐藏或Worker退出宣称暂停。没有桌面租约时直接进入既有圈选流程。该增量不改变状态所有者、外部协议或持久化模型。

## 2026-09-21 圈选语音提交定稿

圈选确认卡已经展示本轮截图与发送边界，用户点击卡片麦克风即授权最终非空转写按当前selection请求直接提交，不再二次点击发送。Desktop只固定语音事件目标并组合既有VI采集与PreviewSession提交；部分转写不外发，最终事件只能消费一次。取消、关闭、重新圈选或超时必须取消采集，不能把同一转写另行作为普通voice输入。

有截图时继续使用Accepted AD-CX-02临时附件协议；无截图时继续使用selection来源的无附件输入。该组合不新增协议、持久化或Agent身份，不改变Application对PreviewSession和VI语音会话的所有权。当前仅授权已有原生证据覆盖的macOS子范围，Windows与多显示器门禁保持。

## 2026-09-21 来源应用显示定稿

确认卡按原始产品范围显示本轮来源应用。Desktop只在用户显式启动圈选、显示覆盖层之前，通过平台原生前台应用API读取一次有界显示名称；Application将其作为PreviewSession临时元数据。重新圈选保留该值，任何会话结束都清零。不可用或不可信名称降级为“当前桌面”。

来源名称只供本机确认卡显示，不自动拼接到问题、不传给Agent、不进入SQLite、事件、Outbox或日志，也不建立持续前台应用监听。该增量不新增协议、持久化、权限或依赖方向，属于Accepted边界内的conforming实现。
