# AD-DS-05 任务列表按创建时间倒序分页

状态：Accepted（2026-09-28，用户明确要求任务空间第一页展示最新任务）。

## 背景

既有 `task.list` 按随机任务 ID 的 BINARY 升序分页。Agent 创建成功后，即使任务空间立即展开并刷新，新任务也可能落在后续页面，用户无法在第一页确认刚提交的任务。展示层反转单页或伪造置顶卡片都会破坏跨页顺序或形成第二事实源。

## 决定

协议 1.32 为 `task.list` 增加默认 `false` 的可选参数 `newest_first`。任务空间的“进行中”和“全部”查询固定请求 `newest_first=true`；SQLite 在授权与状态筛选之后，按持久化创建时间倒序、任务 ID 倒序作为稳定并列顺序，再执行排他游标和页大小限制。

`after_task_id` 保持为不透明排他游标：存储先读取该任务的创建时间，再按 `(created_at, task_id)` 倒序元组继续查询。新建任务在登记事务内写入创建时间；迁移前的历史任务统一为未知时间 `0`，保留在所有有时间任务之后，并以任务 ID 倒序稳定分页，不伪造历史时间。旧会话不请求新字段时继续使用原任务 ID 升序语义。

SQLite 当前状态表仍是唯一事实源。前端只渲染 `task.list` 返回的真实快照，不注入新任务卡片、不修改分页结果。

## 边界与失败

- 不向 `TaskSnapshot` 暴露创建时间，不新增第二查询端点。
- 游标不存在时返回空页，与既有不透明游标行为一致；授权过滤仍在分页前执行。
- 时间相同以任务 ID 倒序确定唯一顺序，避免跨页重复。
- schema 20→21 只增加 `tasks.created_at` 和查询索引；迁移前数据不推测真实时间。
