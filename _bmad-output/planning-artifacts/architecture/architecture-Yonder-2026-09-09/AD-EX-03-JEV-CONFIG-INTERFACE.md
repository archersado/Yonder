# AD-EX-03 Jev 最小配置界面

状态：Accepted
日期：2026-09-22
关联：EX-S2、AD-EX-01、AD-EX-02

## 决策

Yonder 的 Application 层拥有一个最小 Jev 配置模型，只包含非敏感字段：启用状态、服务形态、端点、模型标识、置信度字段、置信阈值、每片段步数/时间/token 上限和允许的执行层。桌面 UI 只负责展示与收集，不直接访问模型、Adapter、配置文件或任务状态。配置通过 Application 校验后由 SQLite Adapter 原子保存为单行 `jev_config` JSON。

2026-10-09 用户变更：Jev 决策门禁的置信度字段与阈值改为显式配置快照。字段只能在 `answer_confidence`（所选答案概率）与 `confidence`（Provider 兼容字段）之间选择；默认使用 `answer_confidence`，既有配置兼容读取为历史 `confidence + 0.75`，避免升级后静默改变已保存策略。Worker 必须严格读取选定字段，字段缺失、非有限数或越界时交回慢脑，不得在两种不同尺度之间静默回退。候选选择和动作后步骤核验使用同一策略快照；阈值范围为 `0..1`。该配置不改变强制 Observe、敏感操作确认、未知结果不重试等硬安全边界。

2026-10-09 用户变更：模型标识不得由 Adapter/Worker 硬编码，必须作为配置快照的一部分传入同一次候选选择与步骤核验。模型标识是最长 128 字节的非敏感受限标识，只允许 ASCII 字母、数字、`.`、`_`、`-`、`/`、`:`，不得承载提示词、URL 查询串或凭据。既有配置缺少该字段时兼容迁移为 `jev-latest`，由用户在设置面板显式改为本地目录实际发布的模型（例如 `english`）。`local` 模式使用经校验的 HTTP/HTTPS base URL；`remote` 模式继续只允许既有 TypeSafe HTTPS 端点。运行时不得再以远端固定值覆盖已保存的本地配置。

2026-09-24 用户变更：设置窗口增加 API Key 密码输入框。该字段不属于 `JevConfig`，仅在用户提交时经本地 Tauri 调用传至 macOS 原生 Keychain 写入端口；读取接口只返回 `credential_configured` 布尔值。Keychain 状态查询与写入不依赖 `TaskHost` 或 SQLite 初始化。空字段不清除旧值，非空字段只可替换，密钥不得写入 SQLite、任务、事件、Outbox、日志、进程参数、环境变量或 UI 回显。

2026-09-22 用户变更：Jev 配置界面是独立的桌面设置窗口，入口放在系统托盘菜单；配置区不得嵌入 Task Space 任务面板。Task Space 只承担任务可见性与控制，配置窗口只承担 Jev 配置。

该配置界面不授权 Jev 执行，也不改变 AD-EX-02 对执行路线的双平台验证门禁。保存成功仅表示配置通过结构校验，不代表模型可用；片段启动时仍须按计划授权值与全局上限取较小值，并在派发前重新校验。

## 后果

- 配置不属于任务状态，不写事件或 Outbox。
- API Key 只保存到 macOS Keychain；设置页不能导出或展示既有值。
- 独立配置窗口只通过本机 Tauri 命令调用 Application；Task Space 不承载配置交互。
- 无效配置必须被拒绝，不能进入片段派发。
- 候选选择与动作后步骤核验必须使用同一配置快照中的模型标识；Worker 不得维护第二份默认模型。
- 候选选择与动作后步骤核验必须使用同一配置快照中的置信度字段和阈值；缺失选定字段必须安全交回，不得自动读取另一字段。
- 关闭 Jev 等同用户控制，运行中片段在下一步决策前冻结并交回慢脑。
