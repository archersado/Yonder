# AD-OCT-03 多任务并行与统一任务空间

状态：Proposed（用户已确认统一展示桌面、文件、文档、浏览器等所有任务并按资源限制并发；协议与执行实现待验证）。

关联：10 月人机协作 Epic、OCT-S1、OCT-S2、AD-OCT-01、AD-OCT-02。Architecture Impact：architecture-change（扩展任务查询协议与并行执行规则）；本记录先于相关协议、OpenSpec 和产品实现，不变更既有状态所有者和模块依赖。

## 用户需求

支持多个任务并行，在 Task Space 查看所有进行中的任务。任务空间是 Yonda 的任务总览界面名称，不引入独立任务引擎；BUA 继续复用 ego-lite Browser Task Space，只关联外部引用和入口，不复制其会话、页面或执行模型。

## 并行边界

- 多个已实现能力的任务可以同时存续和执行；由 Application 按资源约束准入，使用有界执行容量，不无限创建线程或 Worker。
- 不共享互斥资源的后台任务可以并行；同一文件的写入串行，锁粒度使用规范化文件身份。涉及多个文件时统一获取顺序，避免互相等待。
- CUA 保留一个前台桌面租约。多个 CUA 任务可排队但不能同时输入；用户接管后停止该桌面的新动作派发，不自动恢复。无冲突的后台任务无需随之全局暂停。
- BUA MVP 保留单并发；平台尚未提供的 Runtime 不出现在可执行能力中。总览功能不解除 Driver/平台门禁。
- 排队任务展示等待原因，不伪装为 running。本次不直接增加持久化 queued 状态；资源等待的结构化字段及状态映射须在 Rust 契约中明确后实现。
- 取消作用于指定 task_id，不取消其他任务。释放资源须确认执行已停止；副作用结果不确定时仍为 unknown，不自动重试。

## 总览与事实源

SQLCipher 当前状态表仍是唯一事实源。前端仅持有显示快照，不使用组件数组管理真实任务，不另建 Task Space 数据库或全局事件序号。

OCT-S1 扩展只读 task.list：本机用户界面显示其有权访问的全部任务，Agent 查询按 Gateway 的 AuthContext 限定范围，不能仅凭请求里的 agent_id 获得他人任务。沿用 request_id、agent_id、capability、deadline 和 Rust 类型单一来源；响应、分页、筛选和错误模型在实现前补入 AD-OCT-02 契约增量，生成 Schema/TypeScript，不手写第二套类型。

默认“进行中”包括 created、running、waiting-for-user、paused、interrupted；完成/失败/取消进入历史，仍可查询。列表有界分页，不能只显示第一批就称为全部任务。逐任务 sequence 只用于该任务更新，不跨任务比较。新任务发现和筛选变化由列表重新查询处理，分页一致性及删除/终态变化语义需在契约中定义。

每条任务显示名称、来源、状态、当前步骤和等待原因，展开后显示已有的观察/意图与详情；没有真实进度时不用虚构百分比。暂停、取消和继续入口遵循 OCT-S2/S3 的交付门禁。

## 小龙与资源生命周期

只要全局授权任务事实源中存在 running 任务，小龙不得自动隐藏，不受当前选中任务、筛选条件和已加载页数影响。任务状态未知也禁止隐藏。最后一个运行任务结束后重新开始完整三分钟计时；单个任务完成不能清除其他任务的忙碌状态。

## 实施与验收

OCT-S1 负责列表查询、同源总览、并行状态展示与资源准入基础；OCT-S2 验证逐任务暂停/取消、桌面接管和租约释放；OCT-S3 再加入显式归还。执行器、桌面宿主和存储接线分别遵守现有 E0 ADR 门禁。当前文档不意味着已具有并行执行能力。

验收至少覆盖：两个不同资源后台任务同时 running；两个 CUA 任务仅一个持有租约；同文件写入串行；取消一个不影响另一个；超过一页的任务全部可访问；未选中的运行任务仍阻止小龙隐藏；重启恢复全部 running 而不自动重放。Windows/macOS 各自保留原生证据。
