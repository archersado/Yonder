# AD-OCT-06 多任务资源准入核心

状态：Accepted（Application 进程内准入；不含真实执行器和宿主）。关联 OCT-S1、AD-OCT-03。Architecture Impact：architecture-change。

Application 使用单个资源准入实例，互斥锁内一次性检查容量和全部资源再登记，失败不占用任何资源。容量必须为 1..=64，每次最多声明 32 个资源；不建立无界内存等待队列，调用方收到容量/资源冲突原因后保留原任务状态。SQLCipher 仍是任务状态唯一事实源，此表仅表示尚未确认停止的执行资源占用，不缓存任务状态或代替数据库队列。

资源为桌面、浏览器、文件身份；桌面与浏览器各单并发。同一文件身份独占，不同文件可并行。文件身份必须由可信文件 Adapter 规范化并处理路径别名/大小写/硬链接，不能使用外部 Agent 自报路径作为锁键；本批仅验证不透明身份的比较，不声称完成路径解析。空资源集合仍占一个执行容量，供已确认无独占资源的后台操作使用；不能将未声明资源的桌面/文件操作以空集合派发。

成功返回进程内不可克隆的占用凭证。取消请求、超时、unknown 或凭证被丢弃均不自动释放；只有执行器确认停止后显式消耗凭证释放。凭证内部绑定创建它的准入实例，释放接口不接受另一个实例，从类型和接口上避免跨实例释放。所有资源一次性分配，不部分持锁等待；同 task_id 未释放前不得再次准入。用户接管阻断新的桌面准入，既有桌面执行的暂停由执行器负责，后台不受影响；只能由可信宿主显式归还桌面。

准入锁中不执行 I/O 或数据库操作。宿主将来必须先获得单实例所有权并完成 running→interrupted 恢复，再开放执行；每次派发先准入、持久化开始状态再执行，提交失败且尚未派发时可释放，执行结果未知不得释放或重试。资源声明验证、恢复接线、执行停止确认以及用户输入暂停尚未实现，不能直接开放为 Gateway 方法。

本批不增加传输协议、依赖或数据库版本；不接密钥、不改 UI，不解除 E0 平台门禁。没有自动调度、公平排队或语义规划。独立验证覆盖容量、资源原子性、并发竞争、取消不释放、桌面接管与后台隔离。

## 启动用例补充：2026-09-11

可信 Application start 用例串联准入与既有 Start/CAS 事务：先申请全部资源，再提交 created→running，成功返回持久化快照和占用凭证。任何准入失败不写状态；提交失败则确认本用例尚未派发动作，释放本次占用并返回原错误。释放失败独立报告，不返回启动成功。此用例不接受 Resume，不会自动恢复 paused/interrupted，不调用外部执行器；调用方在返回成功之前不得派发动作。

此入口仅供已授权、完成单实例恢复的可信执行宿主，不是 Agent API；资源身份仍必须由可信 Adapter 提供。返回与实际派发之间的用户接管、取消和截止时间检查仍须由执行宿主完成，成功返回不构成可永久复用的执行授权。旧 transition 是内部状态用例，不能用它绕过准入后派发动作。无新增协议或持久化字段。

## 结束用例补充：2026-09-11

占用凭证提供 finish_after_stop：可信执行器确认停止且有确定结果后，只能选择 Completed 或 Failed，使用凭证绑定的 task_id 提交既有终态 CAS/事件/Outbox 事务，再消耗凭证释放占用。调用方不能另传 task_id，避免结束 A 却释放 B。unknown、超时、取消请求不能映射为 Failed；暂停/取消确认留待对应控制用例。

事务失败返回原错误及原凭证，保持占用，允许外部决策后重试状态提交，不重放动作。终态提交后资源释放失败单独返回已提交的 Task 与释放错误，禁止报告数据库回滚或重复提交终态。资源释放与数据库非同一事务：顺序保证不提前释放，失败时保守占用。无真实停止检测或派发实现，不构成产品完成证明。
