# AD-TM-01 任务当前信息与历史事实联合契约

状态：Proposed（已完成当前信息/历史职责与事务边界设计复核；字段级协议、保留和迁移尚未定案，未实现）。关联 TM-S1 / TM-S5、AG-S1、DS-S2。Architecture Impact：architecture-change；不改当前数据库和协议产物。

## 需求来源与建议边界

产品依据为产品简报「Task Space 与权限模型」「MVP 主干链路」以及 addendum「CUA 与 BUA 的 Task Space」：要求发起 Agent、授权、生命周期、资源、事件时间线、产物与审计。架构依据 ARCHITECTURE-SPINE「任务、状态与恢复」：持久化步骤、结果、错误、等待原因、恢复信息和外部引用。AD-OCT-02 明确步骤/观察/意图未交付，不能把本文的少数字段当作完整 Task Space 模型。

具体字段名、字节限额和协议版本属于设计选择，不能宣称来自产品原文。撤回“仅保存最新详情”和“所有元数据仅 running 可更新”的建议：原产品要求持久时间线、产物和审计，进展声明、执行结果、控制记录、用户确认必须分别限定写入语义。禁止据本文直接实施。

## 当前信息与历史保留边界

| 信息 | 当前查询 TM-S1 | 必须保留的历史 TM-S5 | 写入来源 |
|---|---|---|---|
| 发起者、来源、授权引用 | 创建绑定，引用不代表当前授权仍有效 | 创建时有效授权/确认引用；不存凭据 | 可信 AG/本机用户用例 |
| 状态、错误、等待和恢复信息 | 最近已提交值 | 状态变化及影响用户决策的错误、等待、接管/恢复事实 | 可信 Application/执行器 |
| 步骤、意图 | 当前步骤及声明的下一步 | 已接受的步骤/意图声明，标明为声明而非执行证明 | 授权 Agent 或本机显式操作 |
| 动作与 Observe | 当前步骤关联的最近结论 | 对应步骤/动作的执行结果与观察结论，允许缺失/unknown | 可信 Driver 经 Application |
| 资源引用与产物 | 当前关联及最近已知可用性 | 绑定/产出时的身份与版本依据、变更事实 | 对应能力用例 |
| 用户结果确认 | 当前已记录的确认状态，与任务终态分开 | 谁在何种权限下确认了哪次结果/产物版本 | 当前已授权的本机用户操作 |
| 进程句柄、连接和租约 | 不持久化为任务事实 | 只保留必要的生命周期结论，不序列化系统对象 | 宿主/执行器 |

“历史保留”指保留策略允许范围内不可被新事件覆盖；依法授权的删除与配额处理单独规定。最新快照可以覆盖旧值，相关历史事实不能随之被改写。无需用事件重建当前状态，不引入完整 Event Sourcing。

## 最小字段与来源

既有 task_id、owner_agent_id、status、sequence 保持含义。新增字段的规范如下，类型最终只在 Rust 定义，本文不是第二套协议模型。

| 字段 | 含义及上限 | 写入主体 |
|---|---|---|
| title | 可选纯文本，1..256 UTF-8 字节 | 创建时由外部 Agent 或本机用户显式提供，之后不可变 |
| source | local-agent / cloud-agent / local-user / legacy | 可信组合根依据接入上下文绑定，legacy 仅迁移工具可用；请求不能自报 |
| current_step | 可空对象，step_id 沿用任务 ID 字符集及 128 字节上限，label 1..256 UTF-8 字节 | 外部 Agent 经授权用例声明，本机手动任务由可信宿主声明 |
| observation | 可空对象，step_id、result、可空 summary；summary 1..2048 UTF-8 字节 | 可信执行器在 Observe 后提交；不能由 Agent 自报为已验证 |
| next_intent | 可空纯文本，1..1024 UTF-8 字节 | 外部 Agent 或本机显式操作声明；Yonder 不生成下一步计划 |

observation.result 为 matched / not-matched / unknown：只表达对既定条件的验证结果。matched 不代表整项任务已完成，unknown 不代表 failed。不提供条件或未 Observe 时 observation=null，不能伪造 matched。summary 是已允许展示的简短验证描述，不是原始截图、AX 树或命令输出。

文本按 UTF-8 字节拒绝超限，不静默截断写入；禁止空白字符串和控制字符（换行 LF 可用于 summary/next_intent）。所有字段拒绝未知键。null 明确表示未提供/未观察，不能用空字符串冒充已知。名称不从文件正文、命令或页面内容自动推导。

## 更新原子性与归属

创建事务同时写绑定信息、当前状态、创建事件与 Outbox。更新使用按行为划分的可信用例，携带 task_id、expected_sequence；先校验有效权限和作者。Agent 声明、执行器 Observe、用户确认不共用“任意元数据写入”入口。各用例明确自己的完整输入集合和空值含义，不得通过省略或 null 清除其他作者的信息。title 的重命名政策仍待定；source/owner 不允许请求任意改写。

Agent 不能冒充 observation 作者。Observe 必须绑定实际已派发的步骤/动作身份；新步骤不能继承上一步观察作为自己的成功。旧步骤迟到结果不得覆盖当前步骤，但真实迟到事实仍须有明确的历史提交/拒绝报告路径，不能因“不是当前步骤”就静默丢弃。具体执行尝试标识与 TM-S2 联审后确定，不能仅用任务 ID 混同多次执行。

每个接受的任务事实写入同事务更新需要变化的当前记录、递增 task sequence、追加有类型的历史事件和 Outbox 引用。即使仅追加用户确认/迟到事实，任务最新序号也必须与历史同步；任务终态不因此变成 running。旧序号冲突不自动重试动作；发送方观察后决定是否重新提交事实。

重复网络投递的去重与“值恰好相同”分开：同一个明确提交标识、同一作者、同一内容可返回原提交结果；同标识不同内容必须冲突，先检查当前授权。两次真实 Observe 即使摘要相同仍可能是不同事实，不能按文本相同折叠。幂等范围、持久化结构和标识格式是字段级待决项。

新的执行进展声明只在允许派发的阶段提交；暂停/中断不能写成自动继续。停止确认、结果事实和用户确认使用各自规则，不能以 running 单一条件封锁必要审计。终态后不允许追加新的待执行意图，也不修改任务终态；用户确认和合法迟到事实只能增加明确类型的历史及对应非执行展示信息。允许的操作/状态矩阵须在字段级设计完成后固化为 Rust 校验。

## 执行标识设计

依据产品 Task Space 身份/生命周期/审计和架构 request_id、逐任务 sequence、Observe 与 unknown 约束，采用以下设计；具体 Rust 类型尚未生成。

| 标识 | 生成与作用域 | 禁止混用 |
|---|---|---|
| task_id | 可信创建用例绑定到所有者；任务生命周期内不变 | 不用 UI 行号或浏览器 Task Space ID 代替 |
| step_id | Agent/本机任务提交声明，由 Application 在任务内登记；同任务内不复用为另一步 | 不作为已执行证明，不用 label 文本当身份 |
| attempt_id | 宿主在派发一个结构化动作前生成并持久化，绑定 task_id/step_id、动作和执行器；每次显式新执行使用新 ID | 不随连接重建，不等于 request_id；重投递不能生成第二次执行 |
| request_id | 沿用 Gateway 请求 ID，同时标识一次明确的提交操作；重投递同操作必须复用 | 不按摘要文本去重；不同操作不得复用同 ID |
| sequence | 本任务每次已提交事实的有序版本，包括审计补充和用户确认 | 不跨任务比较、不替代 attempt_id 或 request_id |

不额外引入与 attempt_id 同义的 action_id。一次 attempt 对应一个结构化动作及其必要 Observe；一个 step 可以包含多个按序执行的 attempt。当前设计每任务至多一个尚未确认停止的动作尝试，不禁止不同任务按资源规则并行；未来任务内并行须另行评估，不能借“当前步骤”隐式支持多个活动动作。

task/step/attempt/request 沿用既有 ASCII 字母数字、下划线、短横线和 1..128 字节约束；attempt 使用宿主生成的跨重启唯一值，不能重启后把计数从 1 开始复用。外部输入只能引用已登记且有权限的 step，不能选择或覆盖可信 attempt。执行尝试记录持久化所需信息由 TM-S2 提供；表布局本轮不决定。

## 作者与状态允许矩阵

| 操作 | 可信作者 | 允许条件 | 对当前状态的影响 |
|---|---|---|---|
| 创建与绑定来源/授权引用 | 当前已授权创建用例 | 新任务，创建幂等校验通过 | created；不能自报执行器来源 |
| 声明/选择下一执行步骤或意图 | 任务所属 Agent 或有控制权的本机用户用例 | running，任务允许继续派发，旧尝试已停止且必要 Observe 已处理 | 更新步骤声明，不代表动作已执行 |
| 登记执行尝试 | 可信执行宿主 | running；资源、当前授权、接管、取消、deadline 再检查通过 | 原子登记后才派发；不提前报告执行结果 |
| 提交已登记尝试的结果/Observe | 该尝试绑定的可信执行器，经宿主验证 | 尝试确实存在，结果有来源；不接受未知 ID 或伪造作者 | 当前尝试可更新对应详情；旧尝试只补历史，不覆盖新步骤 |
| 提交暂停/取消/等待/停止事实 | 可信控制/执行用例 | 符合 TM-S3 停止协议与状态规则 | 请求与确认分开；仅请求不等于释放资源 |
| 提交新动作或执行意图 | 任意作者 | paused / waiting-for-user / interrupted / 任一终态时拒绝 | 不隐式 Resume |
| 记录合法迟到结果 | 绑定执行器经宿主确认 | 可在暂停、中断或终态记录已发生的事实；不允许借此派发新动作 | 追加审计序号；终态不变、当前步骤不回退 |
| 确认结果 | 当前有权的本机用户操作 | completed / failed / cancelled，明确引用被审阅结果与产物版本 | 新增确认事实，不改变执行终态，不重新执行 |
| 显式恢复 | 用户归还与外部 Agent，经控制用例 | 满足 TM-S4 的重新 Observe 和当前授权；必须无未确认停止的旧动作 | 显式 Resume 后才可登记新的 attempt |

created 阶段可提交非执行的任务目标/名称，但不登记已派发动作。“确认结果”表示用户检查了该次结果，不表示失败任务被确认成功；具体确认意见字段仍须定案。

执行器的结果上报和 Agent 的操作授权是两条边界：权限撤销后禁止新动作及被撤销的读取，但宿主仍须接收自己已派发动作的可信停止/结果事实，不能因此丢审计。失效连接不能自报为原执行器；作者身份从宿主绑定取得。结果上报不授权新的 Observe 操作或输入。

## 重复投递、冲突与迟到结果

提交去重键为 task_id + 可信作者身份 + request_id，记录操作类别、规范化后输入的一致性依据及原提交结果，并与事实同事务写入。当前权限/作者绑定检查在读取去重结果前完成；相同键且内容一致返回原提交的 sequence，不新增事件；相同键不同操作或内容返回冲突。序列化键顺序不同不构成新操作，不把原始 JSON 字符串当一致性标准。去重记录不写原始 Agent Payload 到日志。

确定为首次提交后检查 expected_sequence；旧序号冲突返回当前版本提示，不自动重发动作。相同请求的合法重投递可在任务已有更新时返回原提交结果，客户端不得拿旧回执回退最新 UI。创建任务的既有 idempotency_key 属 AG 创建入口，不能用这里的 task_id 内去重代替。

同 attempt 的同一终结结果不因换 request_id 就允许被写成另一个结论；不一致终结结果进入显式冲突/核实，不静默改写历史。unknown 后获得补充证据作为新的关联事实保留，不修改原 unknown 记录、不自动把任务终态改成成功。两次实际 Observe 需各自明确的观察操作来源，不能靠重复上报伪造第二次观察；其子操作字段与事件 payload 一起定案。

典型断连：attempt 已登记，动作是否执行不可确定 → 标记该动作 unknown，保持停止/资源确认门禁 → 收到可信旧尝试结果时追加关联事实 → 重新观察和外部决策。禁止因客户端重试或 request_id 改变而自动创建新 attempt。跨重启的旧结果只能对应持久化的原 attempt，不接受复用 ID 绑定到新任务。

去重持久化寿命、终结结果/观察事实具体字段和截断删除边界仍是本 ADR 后续门禁；本节不授权新增表或部署行为。

## 数据库与外部副作用提交顺序

1. 权限、字段、提交标识、预期序号和资源/步骤绑定通过校验。
2. 同一 SQLCipher 事务内比较当前版本，写当前信息及必要产物引用，追加对应历史事实和 Outbox，递增同任务序号。
3. 提交成功后才向调用方确认或发布事件；失败全部回滚，不保留成功提示。状态与其必须关联的事实不能拆成两个独立提交。
4. 文件产出、屏幕动作和数据库不是一个原子事务。产物实际创建/校验在能力用例中完成，数据库仅提交受控引用。落盘成功而数据库失败时保留待核实结果，不自动重执行、不删除用户产物，也不报告完整成功。
5. 加密附件就绪后才能提交可读取的引用；准备失败不得提交悬空的“已就绪”产物。临时附件清理和配额归 ST/对应 Adapter，不能用数据库回滚伪称外部副作用已经撤销。

## 读取、事件与容量

list 提供有界摘要，get 提供最新详情。历史事件必须保存审计所需的有界事实或稳定受控引用；“sequence 与变更字段名”的失效通知仅可用于刷新 UI，不能替代历史事实。Outbox 仅引用已提交事件，不复制第二份正文；内部持久化事件与对外投递的字段投影分别做授权与限额校验。

历史查询归 TM-S5，与 TM-S1 同用 task_id/sequence。调用方可先见事件 n 再 get 到更新的 n+1，这是更新后的当前详情，不是事件 n 的历史内容；历史详情必须读取事件自身事实或对应版本引用。序号不能跨任务比较，不引入全局游标。沿用 1..100 的行数分页，但增加正文后还须定义页字节预算和截断/续读语义，未定案前不承诺完整响应上限。

## 历史事件的最小信息（2026-09-12 设计细化）

以下是从产品时间线/审计目标派生的工程契约建议，尚未生成 Rust 类型，不是第二份实现模型。事件外壳包含 task_id、sequence、kind、可信 actor 的类别/内部标识、request_id 和宿主提交时间；步骤/尝试事件另外包含已登记 step_id/attempt_id。排序只按 sequence，时间不作为并发版本。actor 从可信上下文绑定，不回显凭据或任意 Agent Payload。

| 事件类别 | 必须保留的最小事实 | 不包含 |
|---|---|---|
| 任务创建 | owner/source、授权记录引用、可空的显式 title、初始状态 | token、设备密钥、从文件内容猜出的名称 |
| 状态/等待/恢复变化 | previous/status、结构化原因、相关控制或尝试引用、可空获准说明 | 没有事实依据的恢复计划 |
| 步骤/意图声明 | step_id、已接受的 label/intent、声明作者 | 伪装为已派发/已验证的结论 |
| 动作尝试登记 | attempt_id、执行能力标识、已登记资源引用、前置授权引用 | 原始命令参数、输入文字、截图/AX 树 |
| 动作结果 | attempt_id、明确成功/明确失败/unknown、结构化错误、产物引用 | 将动作成功等同任务成功 |
| Observe 事实 | attempt_id、观察轮次、结论、受控证据引用、可空获准 summary | 直接内嵌原始观测数据或猜测成功 |
| 控制事实 | 请求或确认阶段、暂停/取消/接管/归还的类别、关联尝试和作者 | 将发出停止请求记录成已停止 |
| 产物登记 | 产物引用、所属尝试、产出时版本依据和可用性结论 | 无版本依据的永久有效承诺 |
| 用户结果确认 | 被审阅结果的 sequence、产物集合版本引用、检查意见 | 改写执行终态或替用户声称成功 |
| 后续补充 | 被补充事实的 sequence、原步骤/尝试关联、补充的有界事实 | 改写或删除原 unknown、伪造新动作 |

控制和状态可发生在同一事务并各分配连续 sequence；提交整个事务或整体回滚。current sequence 指该事务最后一条事件。事件分条不是拆开提交的理由。结构化原因/错误的具体枚举随各控制/执行 Story 明确，不使用任意完整异常堆栈代替。

观察轮次复用宿主在 attempt 内登记的正整数 observe_index，不新增另一套全局 ID：首次为 1；明确获准再次 Observe 才递增，网络重投递不递增。attempt_id + observe_index 绑定一次实际观察，未知轮次或重复不一致内容拒绝。它是协议设计建议；授权、执行登记与事务形状须 TM-S2 实施时验证。

## 资源、证据与产物引用

事件只保存任务库分配的 reference_id；事件内的显示名称不能作为路径/下载地址执行。引用记录绑定所属任务、种类、创建来源、版本依据和可用性。类别区分原应用资源、生成产物、加密证据附件、外部浏览任务和结果/产物集合清单；它们不是新的独立任务容器。

reference_id 沿用 1..128 ASCII ID 规则。真正路径/外部定位符由可信 Adapter 规范化后保存为受控定位信息，授权解析时才返回必要部分；查询事件不自动访问文件或启动浏览器。每次打开/下载引用都重新检查当前权限和对象状态，不能以持有 reference_id 当授权。

版本依据仅采纳已验证的内容哈希、Adapter 可证明的对象版本，或明确 unknown。文件路径、mtime 和大小组合不宣称等同内容版本；不得为构造版本标识扫描未授权目录。原文件有新的内容时不能覆盖产出时版本依据，原引用报告 changed/missing/unverified 等结果，实际枚举待 FI/DO 联审。用户确认绑定当时审阅的结果与产物集合版本，不自动延伸到后来修改的文件。

大量产物不塞进单条终态事件：使用稳定结果/产物集合清单引用，有界分页读取条目，终态提交前清单已完整且与该结果绑定。清单是产物引用的数据组织，不是任务状态源；禁止为满足限额省掉产物。清单分页契约与具体存储表仍归 TM-S5 实施设计，未就绪时不可把部分清单报成完整。

## 事件与响应预算

工程限额建议（不是产品简报中的数字）：传入请求仍不超过既有 64 KiB；一条对外可序列化事件最多 8 KiB；一次列表、详情或历史响应的完整 JSON UTF-8 编码最多 256 KiB。均在转义和外壳字段加入后计数，不能只统计字符或原始文本。单个显示 label/title 最多 256 UTF-8 字节、intent 1024、summary/获准说明 2048；单事件直接引用最多 16 个。总事件上限优先，字段各自合规不保证组合后合规。

事件写入前验证其规范响应形状可在 8 KiB 内完整表达；不能切碎 JSON、自动删掉必须审计的事实或提交后才发现读不出。普通声明超限拒绝且不写库。Driver 结果正文过大时，只接收具备全部必需状态/错误/关联的有界核心事实和已经获准就绪的受控引用，不能把原始输出灌入事件。附件不可用时明确缺证据/引用准备失败，不编造观察或声称已附完整输出；必要事实不足则不能报告完整提交成功。

事件元信息（actor/ID/request 等）使用已定义的有界 ID，不包含无界扩展字典。内容引用可以受限或失效，但不删除事件顺序和事实核心。list 不携带历史数组，get 不展开无界历史/产物集合；超过详情预算必须在设计上转为独立有界引用，不能等到运行时返回不完整的成功快照。

历史页遵守双重上限：至多 limit（1..100）条，且完整响应不超过 256 KiB。只添加完整事件，预留最终游标/包络空间；达到字节预算即结束该页，不跳过尚未返回的事件。下一游标是最后实际返回的 sequence，has_more 由有界的一条探针判断，不通过全量计数获取。空结果游标维持输入 after_sequence，has_more=false；不得返回空页加 has_more=true 形成死循环。

单事件预算远小于页预算，应保证合法首项可返回；若旧数据/损坏记录不符合预算，返回明确契约/存储错误，不跳过该项。因保留/删除造成缺口另按历史范围契约表达，不能伪装成字节分页跳过。边界回执、错误响应同样有界且不包含正文回显。授权失败优先于读取引用与去重正文。

单条预算和分页选择只限制内存/传输，不授权后台删数据或把内容上传云端。审计/附件总配额与保留策略仍须按原架构单独确认。

## 隐私、日志与录制边界

应用日志与 Outbox 引用不包含正文；已获准的有界历史描述可存 SQLCipher 事件，较大内容只通过加密附件引用。不得因“不写日志”而删除产品要求的审计，也不得因“要审计”而录入密码、完整命令输出或排除的原始数据。敏感源被排除时不生成摘要；无获准摘要则 summary=null。任意自由文本不能保证自动脱敏，Agent 的 title/intent 是声明而非指令，UI 纯文本渲染。录制默认关闭，任务执行审计不等于持续采集用户桌面。

## 保留期限、删除与去重（2026-09-12 设计细化）

来源：ARCHITECTURE-SPINE「个人上下文」规定上下文 90 天、Recording 原始素材 30 天、任务附件 7 天、轨迹与固定内容长期保留；AGENTS 禁止自动删除未同步数据、轨迹或固定内容。这里不将上下文的 90 天自动套用到任务审计，也不将任务附件的 7 天套用到用户产物。

| 数据 | 本期保留设计 | 到期/删除的影响 |
|---|---|---|
| 任务当前状态、结构化事件、确认与引用目录 | 原材料未给出审计 TTL；本期不自动按天删除，直到用户明确删除任务历史；受有界配额约束 | 配额不足限制新工作，不以静默删审计维持运行 |
| Yonder 管理的任务证据附件 | 沿用 7 天；本设计从该附件提交就绪时计算，到期只是清理候选 | 仍被非终态任务使用、未同步、用户固定或仍是受保护轨迹依赖时不得自动删 |
| 原始 Recording 与上下文附件 | 分别沿用 30/90 天，由 RC/CX 的保留规则控制 | 任务引用不改变其所有者，不复制数据以绕过保留规则 |
| 轨迹及固定内容 | 长期保留，但不允许无限占满磁盘 | 配额不足提示处理，不自动删除 |
| 原应用文件、用户输出产物、外部浏览 Task Space | 不归任务历史清理器删除 | 引用失效只能报告；文件删除必须经 FI 的独立确认与回收站语义 |

“任务历史不自动过期”和附件计时起点是本次工程设计选择，不是源文档中的隐含结论。依赖同一附件的保护条件按所有有效引用合并判断，不能因一个任务结束就删掉另一个仍需要的数据。固定任务是否连带固定全部附件需 DS/ST 明确提示和确认，不能偷偷扩大采集或复制范围。

### 区分附件清理与删除任务历史

到期清理只处理由 Yonder 管理且没有保护条件的附件。先在事务中标记引用为清理中并阻止新的解析，登记持久化清理工作；物理文件/索引处理后再确认清理完成。失败保留可重试的清理记录，界面不能提前显示空间已释放。原始事件不改写：引用目录的可用性可以变成 expired/deleted，但事件仍描述当时事实。

自动清理不删除未发送 Outbox，未同步判定来自已确认的投递事实，不能依据“发送过”或 UI 状态。同步状态未知时保守不删。现阶段没有生产同步接线，因此不能假定数据已经同步以启用自动清理。

用户明确删除历史时必须说明影响和是否包括 Yonder 附件；用户文件/外部对象不在该动作内。任务仍活动或存在未确认停止的尝试时先停止并确认，不能删掉仍承担执行控制的记录。固定/未同步记录不得自动删除；若用户明确选择删除这些内容，必须在确认范围内标明，不能把普通关闭详情当授权。

删除先同事务使任务不可再读取/执行、撤除待投递正文的 Outbox 和索引可见性，并登记对应受控清理；物理附件清理完成后才报告清理完成。若数据此前已同步，必须另有不含被删正文的删除同步记录，且在远端确认前显示远端清理未确认。本机删除不得伪装为远端已删除，也不得为了同步删除继续发送旧正文。原有架构要求的关联清理保持，不创建云端服务。

多对象清理不是数据库和文件系统的原子事务；中断后从已登记工作恢复，不重新执行任务。持久化清理结构/远端删除协议归 ST/CX/AG 设计；在它们未实现前不开放“已完全删除”的产品入口，也不在本轮运行清理。

### 去重记录寿命

任务存在期间，任务内提交的去重记录随审计事实保留，不采用短 TTL。序号、操作类别、可信作者和内容一致性依据与原提交结果同事务记录，不能因为附件过期而让旧请求被当成新操作。原回执引用的内容已失效时，只能返回允许访问的原提交事实与失效状态，不能重新执行以补出内容。

用户删除任务历史时，不保留旧正文回执；只保留不含正文的最小防重放标记（不可复用的 task_id 和被删除状态）。后续已鉴权请求不能重建该任务或生成新 attempt；外部错误表现保持不泄露他人任务存在性。task_id 不在同一任务库内回收，创建幂等仍必须由 AG 单独保证，不能只靠任务内去重。

最小标记仍占配额，不把它当无限免费数据；容量耗尽时拒绝新创建而不是回收 ID 允许重放。完整删除本地应用数据/重建设备身份属于独立流程，不承诺跨一次彻底重置保留本库的去重记录。其保留披露、字段隐私和存储格式须后续删除 Story 审阅。

### 历史缺口与配额

证据附件过期不产生任务 sequence 缺口：事件核心仍可读，引用状态说明内容不可用。当前设计不自动删任务事件的中间片段；整任务历史删除后拒绝其历史查询，不返回“完整空历史”。若未来支持部分历史裁剪，须另外定义可读取范围/缺口，而非让当前游标悄悄越过不存在的事实。

本期必须为有界任务/事件/附件及去重记录设置总配额；具体容量尚未由 ST 定案。准入前需保证至少能记录该次有界动作的停止/结果核心事实；不能先派发再因可预见配额满而放弃审计。突然 I/O 故障仍可能发生，必须停止新增派发、保留 unknown/待核实流程，不宣称存储永不失败。限流/配额不能通过后台删除未同步或固定内容解决。

### 产物版本与清单的保留

产出时的版本依据保持不可变。能获得已验证内容哈希/原应用可靠版本时记录；无法保证时明确 unverified，不用路径或 mtime 假冒版本身份。用户确认只能确认已实际检查的某个结果/产物集合版本；若版本未知，记录“已检查但版本不可验证”，不提供后续不变的保证。

产物集合完成前为准备中，完成后作为一个不可变版本发布；新产物形成新清单版本，不修改已经被用户确认的旧版本。条目由清单内部不可复用的顺序键分页，游标同时绑定清单版本和最后返回位置，不与任务事件 sequence 混用。沿用 1..100 条/256 KiB 整响应双上限，无法解析某条产物时保留其失效项，不能漏项或改绑定到另一个文件。清单保留元信息随任务历史，实际附件按各自保留/保护规则处理。

上述是设计方案，没有实际删除、数据迁移或密钥操作。总配额、删除同步与版本/迁移门禁仍需完成，AD 保持 Proposed。
