# AD-TM-02 全量运行状态只读查询

状态：Accepted（2026-09-12，仅 TM-S6 独立核心用例）。

2026-09-14阶段依赖修订：DS研发接线前提遵循Accepted AD-DS-01，不再要求先完成含接线验收的完整DS-S1；可信数据源、恢复完成、唯一Admission及所有真实执行走准入条件不变。Windows最终验证和完整产品完成分别保留。

依据 ARCHITECTURE-SPINE「任务、状态与恢复」、AD-OCT-01 和 AD-OCT-04；承接 TM-S1 AC11 的数据库查询子范围。用户要求后台执行时不能隐藏；本决定不宣称完成收起准入。

复用 TaskStore.running(1)，跨所有归属查询当前表，返回 Running、NoRunningTask 或 Unknown。任何读取错误归 Unknown。只供可信本地宿主调用，不增加 Agent Gateway 方法，不输出其他 Agent 的任务信息。没有运行任务只说明读取瞬间数据库不存在 running 行；不证明执行器已经停止、恢复完成或资源租约释放。宿主未来必须结合 TM-S2 占用与启动恢复门禁，并解决查询与收起之间的新任务竞争。

不改变状态所有者、依赖方向、schema v2、协议 1.0、密钥或技术栈，不依赖 Proposed AD-TM-01。复用有界结果查询；无运行任务时仍可能扫描任务表，不新增索引，真实规模性能验证后再决定索引。DS 接线仍受桌面 Spike 门禁约束。

## 执行占用汇总补充（2026-09-12）

沿用 AD-OCT-06 的唯一 Admission，不复制占用计数。新增只读 has_occupancy，在已有互斥锁内检查任意占用；空资源后台任务也计入，锁中毒返回 Unavailable。不得在锁内读数据库。

TM-S6 的 activity_state 接受当前 TaskStore 和 Option<&Admission>。None 表示宿主未完成单实例恢复/尚无可信准入实例，返回 Unknown；Some 只允许传入完成恢复后的唯一实例。顺序读取数据库 running 快照与瞬时占用：任一已知有工作返回 Busy；两者均确认无工作返回 NoKnownWork；其余返回 Unknown。Busy 优先于另一来源的读取失败，含义仅是已经知道不能收起，不代表另一来源健康。

该结果仍是非原子的观察，不是隐藏许可；查询后新任务准入的竞争由后续 DS 宿主串行接线解决。本轮不持锁执行 UI、不新增缓存/调度器/传输协议，不提前开放桌面产品。用户接管标志不等于执行占用；暂停/取消状态也不能替代真实停止确认。

## 收起预约补充（2026-09-12）

Accepted，仅 TM-S6 进程内协调核心。为关闭观察后新任务准入的竞争，在唯一 Admission 增加 rest_reserved 展示协调标志，不是任务状态。互斥锁内检查无占用、无预约并登记预约；try_acquire 在同一锁内发现预约时返回 PresentationBusy，拒绝派发且不改变任务。预约之后才在锁外查数据库；非 NoRunningTask 撤销尚未展示的预约并报 Busy/Unavailable。

成功返回不可克隆 RestPermit，生命周期覆盖收起动画、隐藏及唤醒。只有可信宿主确认已展开（或根本未开始收起）后显式 release_after_wake；丢弃不解除，窗口操作失败且无法确认展开时保持预约。新任务遇 PresentationBusy 应由未来宿主先唤醒、确认展开、释放后再执行其首次准入，不得自动重放已经派发的未知动作。不增加内部排队或原生窗口代码。

预约与 try_acquire 的竞争具有单一锁内线性化点；所有真实执行必须经唯一 Admission。仅内部直接写 running 仍不构成执行授权。单实例恢复、可信实例和全部执行走准入是前置条件；预约不能替代它们。锁内不做 I/O，数据库查询失败撤销安全，因为尚未返回展示凭证。宿主崩溃后依既有恢复规则重新初始化。无持久化、wire 协议、状态所有者或依赖方向变更。
