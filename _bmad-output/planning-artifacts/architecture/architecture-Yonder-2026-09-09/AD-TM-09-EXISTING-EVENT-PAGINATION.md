# AD-TM-09 既有任务事件的序号分页

状态：Accepted（2026-09-18，TM-S5 只读时间线分页子范围）。

## 背景

TM-S5 首批页面固定读取 `task.events(after_sequence=0, limit=100)`，超过一页时只提示未完整加载。现有协议和 Application 已支持排他 `after_sequence`，事件按每任务严格递增 `sequence` 返回；页面尚未使用该能力。

TM-S5 的 256 KiB 响应预算用于未来可扩展事件 payload、产物和附件引用。当前协议事件只包含有界状态、步骤声明和尝试结果字段，页大小已经限制为 1..100，不需要为已存在字段另建分页协议。

## 决定

Task Space 继续使用现有 `task.events`：首批请求从序号 0 开始，页面每次读取 20 条（协议上限仍为 100）；当最后返回序号小于所选任务快照序号时，用户可显式加载下一页，下一请求的 `after_sequence` 必须等于最后实际返回事件的序号。

页面按返回顺序追加，不从任务快照重建历史、不合并相同内容、不提前移动游标。空后续页、非递增序号或读取失败保留已显示记录并给出局部错误。选择其他任务、刷新或切换列表时，旧分页响应不得写入新详情。

## 边界

本决定不新增协议字段、数据库、事件类型或自动轮询，不声称完成产物、用户确认、保留/删除与新增 payload 的字节预算。新增可变正文或引用前仍须实现编码后 256 KiB 响应预算与有界探针。
