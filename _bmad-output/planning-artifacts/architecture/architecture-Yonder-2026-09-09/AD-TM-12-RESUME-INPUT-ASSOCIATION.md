# AD-TM-12 恢复前的用户输入关联

状态：Proposed（2026-09-18，TM-S4 设计门禁）

## 问题

`agent.input` 是绑定 AgentSession 的通用会话输入，不是任务状态事实。一个 Agent 同时拥有多个 `waiting-for-user` 任务时，按最近任务、最近语音或当前桌面猜测归属会把用户回答交给错误任务，并可能错误恢复执行。

## 候选决定

恢复链路只接受可审计的任务关联：用户从任务详情的“回复此任务”入口，或从该任务显示的明确输入请求进入，宿主在输入开始前冻结 `task_id + owner_agent_id + session_id + task_sequence`。语音与文本都使用同一关联；桌宠独立语音入口没有该关联时仍可按 AD-VI-02 投递会话输入，但绝不触发任务恢复。

输入正文仅在内存保留至目标会话确认，任务库、事件、Outbox 与日志只保存关联建立/关闭、任务序号、会话身份和投递结果，不保存正文。关联只对当次输入有效；任务状态、会话断开、取消或序号变化立即使其失效。多个可接收输入的会话仍按 AD-VI-02 要求用户选择，不按最近连接猜测。

Agent 收到关联输入后仍须自行提出显式恢复请求；Yonder 在该请求时重新检查关联未失效、任务归属、暂停或等待状态、无未确认旧动作，并执行新鲜 Observe。没有关联、Observe 失败、unknown、Recording 证据缺口或任何冲突时保持原状态，绝不自动恢复或重放动作。

## 边界与前置条件

这不是新的 Agent 输入通道，也不把输入封装为 `task.create` 或让 Yonder 规划。它复用 AD-VI-02 的已认证双工会话、TM-S3 的停止事实、RC-S1 的用户行为证据以及 TM-S4 的恢复用例。

RC-S1 目前无法稳定区分真实用户输入与注入输入；在其来源门禁通过前，不实现关联记录、交回或 Resume 产品接口。AG-S5 的 Runtime 当前会话投递能力也必须可确认，特别是 Codex 连接器不能以持久队列代替。Windows 继续按用户决定暂缓。

## 验收门槛

- 两个同 Agent 等待任务并存时，输入只关联用户明确选择的一项；未选择不能恢复任何任务。
- 任务、序号、会话或状态在投递期间变化时，输入结果不能恢复任务。
- 成功关联后的恢复必须经过新鲜 Observe 和 Agent 显式请求；输入投递成功本身不改变任务状态。
- 关联元数据、状态/事件与 Outbox 一致，且不包含输入正文、截图或完整 Agent Payload。
