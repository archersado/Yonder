# AD-TM-15 任务事件响应字节预算

状态：Accepted；日期：2026-09-24。关联 TM-S5、TM5-AC08。Architecture Impact：architecture-change（事件查询契约）；不改变数据库格式、状态所有者或事件写入格式。

## 来源与问题

产品简报「MVP 主干链路」第 9 步和「Task Space 与权限模型」要求可检查任务时间线；TM5-AC08 要求有界读取、稳定序号及明确的不完整范围。现有 `task.events` 按 1..100 条分页，但完整响应尚无字节上限。AD-TM-01 提出的 8 KiB 事件与 256 KiB 整响应预算在本决定内仅对历史查询投影定案；它仍不代表产物、附件、列表及详情已完成同样预算。

## 决定

- `task.events` 的单条已投影事件 JSON UTF-8 编码不得超过 8 KiB；包含 JSON 转义后的实际字节数。超过限额的旧数据或异常记录返回明确错误，不跳过事件。
- 完整 JSON RPC 成功响应（含 `jsonrpc`、`id`、`result`、任务标识和全部事件）不得超过 256 KiB。沿已提交序号遍历，只保留能完整放入预算的前缀。首条放不下则报错，不能返回空页掩盖历史。
- `limit` 继续限制至多 100 条。调用方只用最后实际返回的事件序号作为下一次排他 `after_sequence`；不把未返回项的序号当游标。空页表示本次查询无记录。
- 旧协议客户端仍使用相同事件投影。因预算提前截断时，当前 Task Space 根据最后序号与任务快照序号展示“加载更多”；`has_more` 与显式 `next_cursor` 属后续协议设计，本增量不新增第二套游标。
- 字节检查在 Application 已完成权限与版本投影之后、响应编码之前执行。Adapter 仍只负责按序读取最多 `limit` 条，不能因响应预算删除或修改持久历史。

## 验证

覆盖 JSON 转义、多事件临界值、首项超限、旧协议投影、游标连续性和授权先于读取。Windows 原生验证按用户决定暂缓；本决定只涉及协议/Application 的跨平台纯 Rust 路径。
