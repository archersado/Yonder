# AD-TM-22 任务审计闭环、确认与配额门禁

状态：Accepted（2026-09-23，TM-S5 完整审计子范围）。  
日期：2026-09-23。  
Architecture Impact：architecture-change（协议/持久化/容量门禁）。关联 TM-S5、TM-S1、DS-S2、AG。

## 结论

1. 任务终态与用户结果确认分离。可信本机用户可对已终态任务的**当前结果版本**提交一次确认；确认记录包含被确认的 `result_sequence`、产物清单版本、确认意见和提交标识。重复提交同一确认标识返回既有回执，不追加事件；不同内容冲突拒绝。确认不改变任务终态，不触发再次执行，也不表示产物永远有效。
2. 产物集合使用不可变清单版本。首次确认前生成 `manifest_version=1`；之后新增、替换或失效产物必须生成新版本，旧版本与旧确认保持不可变。清单条目只保存受控 `reference_id`、顺序键和可用性结论，不把路径当作版本身份。
3. 本地审计使用硬配额，不用后台删除自救。MVP 任务审计库上限为 2 GiB，且写入前保留 1 GiB 可用磁盘余量；两者任一不满足即拒绝新创建、新执行或新确认，并给出“审计容量不足”错误。已有历史、未同步内容、固定内容、用户产物和当前运行任务的停止/结果核心事实一律不清除。未来接入附件时，附件计入同一审计配额，不另设无限旁路。
4. 协议升级到 1.20，存储升级到 schema 18。1.20 只新增 `user_confirmation`、`artifact_manifest` 和配额错误投影；1.19 及以下客户端继续收到旧形状，不看见新字段。schema 18 只新增确认、清单、清单条目和配额状态表，不回填旧任务。
5. 迁移门禁：仅允许 15→16，未知版本拒绝启动；迁移前创建同目录快照备份，迁移在单个 `IMMEDIATE` 事务内完成，失败整体回滚。现有任务没有确认和清单时显式为空，不伪造历史。

## 架构影响

- **协议**：1.20 增加 `TaskUserConfirmation` 与 `TaskArtifactManifest`，均为可选投影；旧版本协商时剥除。Rust 仍是 Schema/TS 唯一来源。
- **存储**：schema 18 新增 `task_user_confirmations`、`task_artifact_manifests`、`task_artifact_manifest_items`、`task_audit_quota_state`。确认、清单、事件、任务序号和 Outbox 必须同事务提交。
- **应用**：新增本机用户确认用例与容量校验；Agent 不获得确认能力。配额校验在写路径前置，不在写失败后清理历史。
- **UI**：终态任务显示“结果待确认/已确认”，确认后展示确认版本、产物清单版本和确认意见；产物变化只提示重新检查，不自动覆盖旧确认。

## 验收映射

- **CONFIRM-01**：终态任务可由本机用户确认一次，重复请求幂等，确认不改变执行终态。
- **MANIFEST-01**：清单版本不可变，新增产物产生新版本，旧确认仍绑定旧版本。
- **QUOTA-01**：容量不足时拒绝新增任务/执行/确认，并保留已有审计。
- **VERSION-01**：协议 1.20 与 schema 18 迁移原子完成，旧客户端兼容。
- **MIGRATE-01**：15→16 失败回滚，未知版本拒绝，不伪造确认/产物。

## 非目标

不实现自动清理、云端删除同步、工作流回放、跨设备同步、完整 Event Sourcing、Windows 签名或密钥管理。取消仍按 AD-TM-06 保留数据，不重新开放删除入口。

## 验证要求

需要真实 SQLite 迁移、幂等确认、清单版本不变、配额拒绝、旧客户端字段剥除、Outbox 回滚和 macOS 原生 UI 证据。Windows 按用户决定继续暂缓，不据此关闭完整 Story。
