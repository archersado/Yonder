# AD-VI-03 本地 Agent 语音回复路线

状态：Proposed  
日期：2026-10-14  
关联：VI-S3、VI-S1、AG-S9、DS-S1

## 决策问题

Yonder 需要把当前 Agent 的有界用户可见回复转换为语音，同时保持本地优先、文字优先、运行时轻量、可立即打断，并且不让语音合成阻塞 Agent、任务或四类执行链路。现有 VI-S1 只定义输入侧 ASR，不能把 TTS 偷塞进其已审范围。

## 候选路线

1. 系统原生本地 TTS：macOS 与 Windows 分别使用系统公开语音合成能力，通过同一 `VoiceSynthesisPort` 收敛。依赖最少，但本地中文声音、离线性、停止语义、回调和输出设备行为必须用统一样本实测。
2. 单一跨平台嵌入式本地 TTS：仅当系统原生路线无法满足两端统一契约时评估；模型许可、体积、内存、首包延迟、签名与升级必须有界。
3. 云端 TTS：不作为默认候选。未来若产品明确要求，必须另行定义正文外发、凭据、费用、失败和用户确认，不得作为本 Story 的静默回退。

## 拟议决策

- 优先验证路线 1；ASR 与 TTS 是独立 Port，不相互调用。
- 回复采用异步流式处理：稳定句可并发合成，但 Application 按 `reply_id + generation + sequence` 有序播放。
- TTS 失败降级到已有文字回复，不改变 Agent turn 或任务结果。
- 用户停止、关闭回复卡或开始新一轮收音时，使当前 generation 失效并停止播放；不自动取消 Agent turn。
- 语音回复默认关闭，仅朗读 AG-S9 已筛选的最终用户可见正文。
- 不持久化正文、合成音频或振幅，不在日志、事件、Outbox 和 SQLite 记录这些内容。
- 播放状态是 Application 短生命状态，不是任务状态；可选形象提示不改变 DS 的九种可信状态。

## Spike 门禁与期限

在 2026-10-18 前建立统一中文样本并完成候选能力探针；缺少 Windows 环境时必须明确记录阻塞，不得用 macOS 证据接受本 ADR。统一样本至少覆盖首句延迟、十句顺序、停止到静音延迟、收音打断、迟到回调、离线、缺失语音包、设备切换、Markdown 转朗读文本和资源释放。

路线 1 任一平台出现以下情况即淘汰或要求新的架构审阅：需要常驻第二应用、无法证明停止、静默联网、要求落盘正文/音频、无法提供稳定错误，或资源占用不满足常驻桌面产品。ADR Accepted 后才能创建 VI-S3 产品实施 OpenSpec；验证失败返回路线评估，不以双执行栈长期兜底。
