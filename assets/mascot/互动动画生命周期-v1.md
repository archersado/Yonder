# Yonda 小龙：互动动画生命周期

状态：交互设计草案，尚未实现动画或任务状态接线。

2026-09-11 实施进展：E0-S1 Spike 已接入呼吸、双眼闭合与点击点头，ego-browser 页面验证通过，详见 `openspec/changes/e0-validate-desktop-foundation/verification-animations.md`。其他生命周期动画和任务状态接线仍未实现；眨眼使用眼区遮罩叠加，不是完整序列帧。

依据：ARCHITECTURE-SPINE 的九种桌宠展示状态。角色使用已选定的小龙形象，窗口基准为 200×200、透明背景。此文定义表现与触发条件，不新增任务状态、任务规划或第二状态所有者。

## 核心体验

2026-09-14用户变更：全部九种状态均保留自然呼吸和眨眼，当前眨眼间隔3～5秒。呼吸/眨眼与主动作独立叠加，不重播成功/失败、不改变任务语义；拖动、隐藏和系统减少动态效果仍按既有优先规则。执行双短臂从肩部交替抬爪/落爪，方向主要上下，不能只旋转裁出的掌部贴图。当前四态先复验，其他五态尚无真实事件接线，不据此宣称全生命周期完成。

小龙像一个安静、专注的伙伴：平时轻轻呼吸，收到请求时抬头，工作时认真，完成后短暂开心。遇到阻碍时请求帮助，不用庆祝动画掩盖失败或等待。

常见流程：待命 → 收到请求 → 等待外部 Agent 响应（如有明确事件）→ 执行 → 成功或失败 → 待命。执行过程中可以进入等待用户或暂停；继续执行必须由真实任务事件驱动。手动录制走独立入口，不随点击或任务执行自动开启。

## 九种状态动画

| 状态 | 动画 | 动作设计 | 节奏与结束条件 |
| --- | --- | --- | --- |
| `idle` 待命 | 小龙呼吸 | 身体轻轻起伏，偶尔眨眼，尾尖缓缓摆动 | 呼吸每轮约 3.6 秒；眨眼间隔 6–10 秒；持续至新事件 |
| `listening` 收到请求 | 抬头侧耳 | 小龙轻抬头、略微歪头，翅膀收拢，目光朝向用户 | 入场约 350 毫秒，随后安静停留；只在真实交互会话中展示，不表示麦克风已开启 |
| `thinking` 等待响应 | 好奇歪头 | 缓慢交替轻歪头，尾尖小幅摆动 | 每轮约 2.4 秒；由外部 Agent 等待响应事件进入，收到下一事件退出；Yonda 不承担语义规划 |
| `executing` 执行中 | 认真挥爪 | 小幅交替挥爪，身体略向前倾，小翅膀偶尔轻动 | 每轮约 1.4 秒；仅真实 running 状态循环，不表达虚构进度百分比 |
| `waiting_for_user` 等待确认 | 举爪求助 | 举起一只爪子，轻歪头看向用户 | 入场约 500 毫秒，随后保持姿势；每 8 秒最多一次微弱提示，不反复跳动；用户处理后按真实状态退出 |
| `paused` 已暂停 | 安静收翼 | 翅膀收回、身体放松，保留慢呼吸 | 过渡约 300 毫秒；持续至显式恢复或结束，点击小龙不自动恢复任务 |
| `recording` 手动录制 | 专注记忆 | 小龙保持专注姿势，尾巴缓慢摆动，爪边显示小红点 | 红点稳定显示，外围可每 2 秒轻柔变化；仅用户手动开始录制后出现，停止后立即撤下；始终提供可理解的录制状态与停止入口 |
| `success` 已完成 | 开心小跳 | 轻跳一次，翅膀短暂展开，笑着挥爪 | 整段约 1.2 秒，只播放一次；落地缓冲后回到待命，完成信息仍保留在任务记录 |
| `failed` 未完成 | 低头再抬头 | 轻轻低头，随后抬头看向用户，表达需要帮助 | 整段约 1.4 秒，只播放一次；回到待命或当前任务展示状态，错误信息保留，不自动重试 |

所有动画只作用于窗口内的图像，不通过移动操作系统窗口制造跳动。跳跃、挥爪和翅膀展开的每一帧必须留在透明画布内，避免被窗口裁切。

## 直接互动与生命周期衔接

这些是短暂动作，不是持久化任务状态。

| 交互 | 表现 | 行为约束 |
| --- | --- | --- |
| 首次显示 | 轻轻出现并挥爪，约 650 毫秒 | 不伴随声音，不移动用户已选定的位置 |
| 鼠标靠近 | 微微抬头，约 180 毫秒 | 不抢焦点、不弹窗；离开后平滑恢复 |
| 单击 | 点头回应，约 400 毫秒 | 只表达“注意到你了”，不表示接单、成功或授权 |
| 按住拖动 | 收起装饰性动作，保持稳定姿势 | 保留原生窗口拖动；不得误触单击反馈 |
| 松开拖动 | 轻微落稳，约 250 毫秒 | 松开后从当前真实状态继续，不将执行中误重置为待命 |
| 隐藏与重新显示 | 隐藏时停止动画计时；显示后恢复当前状态 | 不重播旧任务的成功、失败或重复入场动作 |
| 退出 | 立即退出 | 不用告别动画延迟退出或阻止关闭 |

## 状态来源与打断规则

1. 任务动画只消费 Application/Gateway 提供的真实快照与事件。UI 仅管理动画播放时间、鼠标交互等短暂视觉数据。
2. `thinking`、`listening` 等展示状态必须有明确的真实来源；来源未接线时不伪造工作循环。
3. 录制指示独立保持可见，不被庆祝、点击或其他任务动画覆盖；录制由用户手动控制。
4. 隐藏、退出与减少动态效果设置优先；拖动时停止装饰性循环，录制标记仍保留。
5. 等待确认、暂停、失败等事件到达时立即打断执行循环。新任务开始时可以打断旧任务的庆祝，不等待庆祝播完。
6. 成功和失败仅在新事件到达时播放一次；重新挂载窗口、显示窗口或重复读取快照不得重播。未来任务接线按 task_id 与 sequence 去重。
7. `unknown`、`interrupted` 等情况不可映射为成功；使用暂停或待处理表现，并在任务详情保留原始状态和恢复要求。

## 动作强度与素材交付

- 以 200×200 窗口为基准，呼吸缩放约 1%–2%，歪头不超过 4°，成功小跳不超过 8 个逻辑像素。角色四周预留安全边距。
- 不默认播放声音，不高频闪烁，不用整窗透明度闪动作为提示。
- 遵循系统减少动态效果偏好：关闭循环、跳跃和旋转，保留静态姿态与必要状态标记。
- 当前单张 PNG 可先实现整体呼吸、轻歪头、点头和小跳。眨眼、独立挥爪、收翼和尾巴摆动需要同角色透明 PNG/WebP 序列帧，不能把整张图片拉伸当作局部动作。
- 后续序列帧保持相同画布、脚底锚点和角色比例，逐帧验证透明边缘；桌宠素材包只交付声明式数据与 PNG/WebP，不包含可执行脚本。
