# AG-S1 调用交互设计

## 调用方流程

外部调用方先完成传输认证，再hello协商能力，成功后只读任务。未握手返回-32002；请求身份不匹配-32003；越权任务与不存在同为-32004；主版本不兼容-32010；过期-32001。能力只声明已实现task.read，不声明任务创建或执行。

本批无新增UI。桌宠仍根据TaskHost真实快照展示，不因hello播放接单/执行/成功动画。Agent查询不会改变小龙动作或任务状态。本机任务面板保持当前轻量交互与读取失败反馈。

## 可观察性与平台限制

库返回结构化协议响应，不用日志泄漏任务信息；测试仅保存通过状态和协议错误断言。未来CLI/MCP需明确标准输出协议、标准错误诊断、断连/重连及权限反馈。Windows暂缓，当前库测试不冒充原生接入通过。

## 入口与流程

Agent连接认证后hello，再查询/创建已有职责内任务；用户只操作已有任务。

## 状态与错误反馈

真实状态、拒绝和不可用可区分，不用桌宠动作假装创建或执行成功。

## 无障碍与平台验证

当前无新增界面；后续复用可访问任务菜单，原生平台证据分别验证，Windows暂缓。

## 正式宿主私有stdio研发接入

依据Accepted AD-AG-03及用户本地Agent测试变更：可信父进程显式启动--local-agent-stdio，固定研发Agent身份，真实TaskHost共享，不另开库。AC1/2/4/5复用Gateway门禁；AC6生产认证仍未满足。Agent仅登记created，已有菜单有任务悬停可见、移入可操作、移出消失；坏帧/EOF终止连接，普通启动不开放入口。Windows暂缓；原生证据与stdio证据分别保存。

## 未开始取消协作

Accepted AD-TM-04由TM-S3首批实现created取消；Agent协议1.2协商task.cancel，用户入口固定LocalUser且仅task-space窗口。详情选择created后提供取消任务按钮，提交中禁用、成功刷新、全部保留取消态、失败提示；不提供执行中取消/接管伪实现，也不新增人工创建。原生证据归tm-s3-pending-cancel，Windows仍暂缓。

## 本地 CLI 与 MCP 交互

入口是`codex mcp add yonder -- yonder mcp`，无新增桌面窗口、托盘项或人工创建入口。连接成功后Codex看到结构化工具；调用创建后，既有小龙播放收到请求状态，任务菜单显示Agent提供的名称。Yonder未运行时MCP工具返回“Yonder未运行”；非法参数和任务冲突返回短错误，不打印请求正文。

stdio只输出MCP JSON，诊断写stderr。键盘与无障碍由Codex CLI自身承担；Yonder任务菜单继续使用既有可访问按钮。macOS验证真实Codex/MCP进程、UDS所有权、无TCP和单桌宠；Windows证据暂缓且不得标记通过。

## 云端 Connector 交互

Yonder保持轻量桌宠形态，不为云连接增加全屏页面。未配置时显示“云端Agent未连接”；连接中、已认证、重连等待和认证失败使用文字状态与可访问名称，不能只靠徽标颜色。只有认证并声明`user_input`后，桌宠才显示“Agent已连接”。

登录、设备配对、凭据撤销属于外部平台契约；尚未提供时不展示虚假的“连接”按钮。网络断开不得让本地任务动画消失或改写任务状态；需要用户处理认证时显示明确入口，后台重连不反复抢焦点。

## 快慢脑模式调用反馈

本增量不新增桌面窗口或手动创建计划入口。Agent 在原有连接中协商计划能力，提交成功只表示计划已被可信用例接受；不直接播放「任务完成」或伪装 Driver 已动作。能力未开放、身份/版本冲突、计划过期或 Gateway 断连返回可区分的结构化错误，不输出计划正文。快脑交回时，现有任务面板可显示「等待 Agent 重新规划」及最小原因；具体文案与状态所有权由 EX-S2/TM-S5/DS-S2 定稿，AG-S1 不另建 UI 状态。键盘与无障碍继续使用现有可访问任务菜单和 Agent 客户端；Windows/macOS 原生证据按各自传输与展示入口提交。
