# AG-S10 产品需求

## 问题与目标

当前圈选卡点击发送后，只要投递返回拒绝、未知或本地错误，原生会话和 WebView 都会立即删除截图并清空输入框。用户既无法确认错误原因，也无法修正问题或安全重试。

## 需求来源与验收映射

- 原始需求：产品简报“桌宠是轻量交互入口”、CX-S2“屏幕圈选后提问”。
- 后续用户变更：2026-10-10 用户报告“点击发送后没有发给 Agent，图片消失、输入框置空”，要求统一由 Yonder 返回 Agent 消息。
- 架构约束：AGENTS.md 数据安全与 Agent Gateway 规则、Accepted AD-CX-02 的同会话 4 MiB 附件上限、AG-S9 的运行时回复关联。
- 待审设计建议：失败恢复只保留内存数据，不引入持久化或静默压缩。

## 验收条件

- AC1：只有 Agent 返回 `accepted` 后才清除提交用的图片与问题；等待回复的卡片仍可展示原预览。
- AC2：Agent `rejected` 或发送前校验失败时恢复可编辑状态，保留图片和问题，允许用户修正或安全重试。
- AC3：`unknown` 保留现场并明确提示“不得自动重试”，发送按钮保持禁用，避免重复副作用。
- AC4：超过 4 MiB 的附件在进入 Agent 分块协议前返回明确的“附件过大”，不退化为泛化拒绝。
- AC5：无 Agent、目标未选择、不支持附件、附件无效、回复忙和通道异常分别显示可操作反馈，不记录正文或截图。
- AC6：明确关闭、重新圈选和 accepted 后的既有结束路径继续清理临时数据。
