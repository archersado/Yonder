# AG-S11 产品需求

## 问题与目标

Agent 回复目前以 `textContent` 和 `white-space: pre-wrap` 显示，Markdown 标题、列表、代码块和强调符号原样暴露，长回答难以阅读。目标是在 Yonder 内提供安全、流式兼容的 Markdown 展示。

## 需求来源与验收映射

- 原始需求：产品简报“桌宠是轻量交互入口”与 AG-S9“原确认卡显示 Agent 回复”。
- 后续用户变更：2026-10-10 用户明确要求“Yonder 的返回需要支持 Markdown 渲染”。
- 架构约束：AG-S9 的 64 KiB、有界内存、严格序号和不持久化规则；AGENTS.md 禁止记录正文和完整 Agent Payload。
- 待审设计建议：采用本地 DOM 白名单渲染，不增加通用 Web 内容执行能力。

## 范围与非目标

支持段落、换行、一级至三级标题、无序/有序列表、引用、围栏代码块、粗体、斜体、删除线、行内代码和安全链接文本。

不执行原始 HTML、脚本、事件属性、图片、iframe、自动外链请求或任意协议 URL；不做完整 CommonMark 兼容承诺，不持久化渲染结果。

## 验收条件

- AC1：流式 delta 到达后，当前累计正文重新渲染，最终能展示规定的块级与行内 Markdown。
- AC2：未闭合的流式语法安全降级为文本，后续 delta 补齐后可正常渲染。
- AC3：原始 HTML、脚本、Markdown 图片和危险 URL 不产生可执行或可加载 DOM。
- AC4：纯文本、空行、超长单词、代码块与复制选择保持可读；失败、中断和截断状态不回归。
- AC5：回复正文和渲染 DOM 只存在当前卡片内存，关闭后清除。
