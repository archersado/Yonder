# AG-S12 产品需求

## 问题与目标

当前圈选回复卡虽已接入受限 Markdown，但列表的显式标记和段落层级在实际卡片中不够稳定，用户仍会把回复误认为未渲染的纯文本。卡片又是无边框窗口，自动定位后不能由用户移开，可能遮挡被询问内容。

## 需求来源与验收映射

- 原始需求：产品简报“桌宠是轻量交互入口”、CX-S2 圈选提问与 AG-S9 原卡回复。
- 后续用户变更：2026-10-11 用户明确指出“Markdown 还是没有显示对”，并要求“圈选的窗体应该支持拖拽”。
- 既有规格：AG-S11 要求标题、段落、列表、引用和代码具有可读语义；本 Story 修复其实际呈现并增加窗口拖动。
- 架构约束：回复正文继续只驻内存；不得放宽 HTML、脚本、外部资源或危险 URL 安全边界。

## 范围与非目标

1. 为无序、有序列表提供稳定可见的项目标记、缩进和松散列表支持。
2. 保持流式累计重渲染，未闭合语法继续安全退化。
3. 允许从卡片标题区原生拖动确认/回复窗口；正文、输入框、按钮和图片区域不触发拖动。
4. 拖动只改变当前短生命窗口位置，不持久化坐标。

不引入完整 CommonMark 引擎、HTML 执行、窗口缩放或跨重启位置恢复。

## 验收条件

- AC1：连续列表和项目间含空行的松散列表均形成单一语义列表，项目标记与编号清晰可见。
- AC2：标题、段落、引用、代码和行内强调继续按 AG-S11 安全渲染；危险内容仍为惰性文本。
- AC3：用户按住卡片标题区拖动时，原生窗口随指针移动；释放后输入、复制、滚动和按钮仍正常。
- AC4：从正文、代码、输入框、图片或按钮开始拖动不会移动窗口或吞掉原交互。
- AC5：关闭、重新圈选或重启不保存卡片坐标；协议、SQLite、事件和 Outbox 均无变化。
