# AG-S13 产品需求

## 问题与目标

AgentInputHub 在多个在线会话并存时会清空自动目标以避免误投，但 Agent 管理仅能管理 Agent 注册状态，不能选择在线会话。错误提示给出了用户无法完成的动作。产品必须让选择入口与错误提示闭环，并继续保证输入不会被猜测投递到错误 thread。

## 范围与非目标

### 范围

1. Agent 管理展示当前进程内在线、支持用户输入的 AgentSession，不展示完整 session/thread 标识。
2. 每个在线会话使用不透明短生命 `session_ref`，用户可将其中一个设为当前接收目标。
3. 只有一个会话时自动选中；第二个会话出现时，尚未显式选择的自动目标失效并要求选择。
4. 显式选择后，其他会话连接或断开不得改变目标；目标断连时清除选择，并在只剩一个会话时自动选中。
5. 圈选、直接语音和后续同类用户输入共用同一运行时目标，不改变任务归属或 Gateway 认证。
6. 会话列表与选择只驻运行时内存；不得进入 SQLite、事件、Outbox、日志或索引。

### 非目标

- 不保存“上次选择”，不自动恢复历史 thread。
- 不建立聊天历史、会话重命名、跨设备路由或云端会话目录。
- 不允许 UI 提交原始 session_id，也不改变 Rust Gateway 协议。
- 不把 Agent 注册启用/禁用与当前在线会话选择混为一体。

## 验收条件

- AG13-01：零会话显示无可接收会话；单会话自动选中且输入可直接提交。
- AG13-02：第二个会话出现时，若当前目标仅为自动选择，输入被拒绝并在 Agent 管理提供两个可选目标。
- AG13-03：选择一个 `session_ref` 后，圈选输入只进入该会话，其他会话不收到正文或附件。
- AG13-04：显式目标在非目标会话连接/断开时保持；目标断连后不得继续投递到失效引用。
- AG13-05：目标断连且只剩一个会话时自动选择剩余会话；仍有多个时继续要求用户选择。
- AG13-06：UI 只显示 Agent ID、进程内会话序号、连接/能力状态与当前目标，不显示完整 session/thread ID。
- AG13-07：选择失败、会话已断开或锁异常给出稳定反馈；圈选卡在缺少目标时直接提供“选择接收会话”入口，原问题与截图继续保留。
- AG13-08：选择状态不持久化，不改变任务状态、回复正文边界或 Agent 注册授权。

## 需求来源与验收映射

| 类型 | 来源 | 对应验收 |
|---|---|---|
| 后续用户变更 | 2026-10-14 用户要求继续真实 Agent 回复语音验证 | AG13-01～08 |
| 真实产品缺口 | 多会话时提示选择，但 Agent 管理没有选择入口 | AG13-02、03、07 |
| 既有架构 | AD-AG-11 的当前输入/回复短生命关联与禁止猜测 | AG13-03～08 |
| 安全边界 | 完整 session/thread ID、输入正文和选择状态不得持久化或记录 | AG13-06、08 |
