# AG-S4 调用与交互设计

## 入口与流程

用户以“使用 Yonder……”表达目标，Agent加载统一 Skill。Skill先确认 Yonder Runtime 与可用能力，再创建具有简短真实名称的任务；之后根据目标读取对应的 BUA、CUA、Document 或 Command 子模块。用户不需要选择底层 Driver，也不会看到第二个桌面应用。

## 任务可见性

任务创建后沿用 Yonda 轻量悬停面板和生命周期动画。步骤、执行、等待用户、外部等待、成功、失败、暂停和接管必须来自 Yonder 真实事件；Skill 文本不能直接驱动或伪造桌宠状态。BUA 页面仍显示在 ego-lite Task Space，Yonda 只展示任务摘要和控制入口。

## 用户接管与确认

BUA 需要用户登录、处理浏览器权限或接管时，Skill请求 Yonder hand-off 并停止页面动作；交回后恢复同一 Task Space。CUA 接管遵守停止确认和工作定位门禁。Document覆盖、Shell、提权、安装、删除、支付和发送在实际操作前显示明确对象、范围和后果，取得授权后才调用对应能力。

## 状态与错误反馈

Yonder未运行时提示先启动 Yonda；能力未发布时明确说明“当前 Yonder 尚不支持该能力”，不切换到旁路工具。序号冲突先读取最新任务事实；unknown、Observe失败、目标丢失或用户输入中断时保持任务可见并说明下一步，不自动重试副作用。

Skill 的终态回执区分完成、取消、暂停、接管中和结果待核实。错误内容保持简短，不展示正文、截图、输入、完整命令输出或完整 Payload。

## 无障碍与平台验证

Skill 以结构化工具结果和文本反馈为主，不依赖颜色或动画表达唯一状态。Yonda现有控件保持键盘和辅助功能可操作；ego-lite 用户交接沿用其可见控制。macOS与Windows能力分别声明，Windows暂缓不应隐藏平台缺口。
