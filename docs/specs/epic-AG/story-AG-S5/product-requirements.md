# AG-S5 产品需求

## 问题与目标

Yonder的语音、圈选提问等显式用户入口生成最终输入后，应主动交给操作发生时绑定的已连接Agent会话。Yonder不回答、不规划、不替Agent创建任务。

## 范围与非目标

本 Story 只负责把已完成的用户输入投递给明确绑定的 Agent 会话；不实现语音识别、任务规划、Agent Runtime 或云端服务。

## 验收条件

- AG5-01：本地或云端Agent Runtime的会话显式声明可接收用户输入，Yonder不按进程名、传输类型或厂商猜测目标。
- AG5-02：输入携带`input_id`、来源、正文、创建时间和deadline；正文有长度上限。
- AG5-03：Agent确认接收后才显示成功；断连、超时或拒绝均显示失败，同一输入不自动重试。
- AG5-04：语音最终结果自动投递；用户开始收音即授权该轮投递，不增加确认页。
- AG5-05：输入不直接调用`task.create`；任务仍由Agent决定、命名并经Gateway创建。
- AG5-06：日志、任务事件和Outbox不记录输入正文；MVP不持久化失败输入。
- AG5-07：本地UDS/Named Pipe与云端主动WSS复用同一`agent.input`协议及accepted语义，不形成两套输入链路。
- AG5-08：多个Agent同时连接时，任务内输入投递给任务归属会话；桌宠独立输入投递给显式激活会话。只有一个可用会话时可自动激活，目标不明确时不得猜测投递。
- AG5-09：用户中断当前Agent turn后，后续输入仍可独立进入同一会话；不得因Agent内部待处理队列残留而阻塞。
- AG5-10：桌宠持续体现当前是否存在可接收输入的Agent连接；首个连接建立或最后连接断开时立即更新并唤醒隐藏中的桌宠，不轮询任务数据库。

## 来源与映射

- 原始需求：产品简报“Yonder是Agent Tool”“Agent Skill + 本地主机接入”→AG5-01、03、05。
- 后续用户变更：2026-09-17“语音不应该确认，直接输入给智能体”→AG5-02～04。
- 后续用户变更：2026-09-17“中断后面的消息不能卡住；不修改Codex机制”→AG5-03、09。
- 后续用户变更：2026-09-17“Yonder是否连接Agent要在桌宠状态上体现”→AG5-10。
- 架构约束：ARCHITECTURE-SPINE Agent Gateway、本地/云端统一用例、协议单一来源、日志正文禁令→AG5-01～03、05～08。
