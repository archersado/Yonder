# CM-S1 视觉交互设计

## 入口与流程

Agent 先提议；提议成功后，Yonda 旁自动展开既有 Task Space、切到“全部”、选中对应任务并把本机批准卡滚动到可见位置，不要求用户点击小龙后再进入任务详情。批准卡展示 program、字面 args、cwd、显式环境、超时和风险提示，并提供“批准执行一次”与“拒绝”；不得把完整命令显示在桌宠形象窗口、顶部执行浮窗、任务标题或远端 Agent。Agent调用通过结构化响应观察`awaiting_user/running/stopping/exited/unknown`；停止中和unknown区分。正文输出只在获准响应中有界返回，不进入日志。

## 状态与错误反馈

批准前自动透出的卡片显示“等待你的批准”，关闭、拒绝、到期或撤权显示稳定原因且不得触发 Runtime。若自动展示失败，提议仍保持等待且手动 Task Space 入口可用，不能自动批准或改变任务。批准只对当前一项命令有效，参数或任务变化后提示需重新提议。加载、等待、失败和未提供能力不能伪装为完成。

## 无障碍与平台验证

有 UI 的按钮提供名称与可见焦点，支持键盘，减少动态效果遵循系统偏好；无 UI 时保证调用错误稳定可区分。原生交互须各平台独立证据。

## 待决事项

批准入口只在受信任的本机 Task Space，Agent Gateway、CLI/MCP 只可看到不透明引用和状态。Windows 显示“当前平台暂不支持”，不得显示可执行按钮。Shell、提权、安装、删除、支付和发送不提供此入口。

## macOS Runtime 调用反馈

内部调用方区分 `exited / timed-out / cancelled / output-limit-exceeded / unknown`；非零退出显示退出码而不是“系统不可用”。超时、取消和输出超限只有在完整进程组停止已确认时才显示对应确定结果，否则显示“结果待核实”。stdout/stderr 截断不得隐藏为普通成功，也不得进入日志、桌宠提示或任务名称。
