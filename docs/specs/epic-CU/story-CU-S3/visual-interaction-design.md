# CU-S3 视觉交互设计

## 入口与流程

后台原生动作运行时，小龙保持在用户当前桌面，以轻量“后台执行”小图标和对应忙碌动画反馈，不打开全屏界面、不抢焦点。状态变更沿用宿主事件主动唤醒隐藏中的小龙；减少动态效果开启时保留静态图标和文字状态。

动作需要前台桌面时，小龙显示“需要桌面操作”；只有Agent显式提交CUA步骤并取得桌面租约后才显示正在执行桌面操作。失败、unknown和能力不可用使用既有失败/等待状态，不伪装为完成。

## 状态与错误反馈

后台执行、需要前台、桌面执行、失败和unknown均来自宿主提交事实。能力不可用显示稳定原因；无Observe证据时不得显示完成。小图标不替代任务状态，点击或悬停仍按既有Task Space入口展示详情。

权限未决定或失效时，小龙切换为“等待用户授权”，Task Space显示权限名称与显式入口；用户未操作前不播放后台忙碌动画。系统授权完成后重新Observe，原任务不自动重发副作用，由Agent决定是否提交新步骤。

## Task Space 时间线

悬停任务面板中，后台动作与CUA动作位于同一任务详情时间线，并按sequence排列。每项显示：步骤名称、执行类别（后台原生/桌面操作）、开始与结束阶段、Observe结果、稳定错误分类。后台运行中的任务仍出现在“进行中”；暂停、取消和终态遵循现有分面。

时间线不显示输入正文、截图、完整输出、完整Agent Payload或原生对象身份。证据过长时只显示摘要和“未完整显示”提示。

## 交互与无障碍

桌宠图标提供可访问名称；Task Space条目支持键盘进入和清晰焦点。鼠标从小龙移入面板可继续操作，移出小龙与面板后按既有规则关闭。后台动作不弹出新窗口；需要授权或前台操作时给出明确原因，由既有确认或接管入口处理。

## 无障碍与平台验证

状态图标同时提供文字或可访问名称，不只依赖颜色和动画；键盘焦点清晰，减少动态效果开启时不影响状态辨识。涉及UI、系统API和权限的实现必须分别提供Windows/macOS原生证据；当前Windows暂缓。

## Spike呈现

首轮Spike无产品UI，只以结构化结果验证前台未改变、动作结果、Observe与无隐式改道。产品图标和时间线接线必须等待ADR接受及独立Verification Goal。
