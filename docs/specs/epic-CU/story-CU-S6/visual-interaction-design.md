# CU-S6 视觉交互设计

## 入口与流程

临时 transcript 与元素句柄不直接展示在顶部浮窗或任务面板。用户仍只看到慢脑提交的步骤标签、当前执行步骤、成功/待核实图标及交回原因，不看到 AX 标签、索引或完整控件树。

计划执行响应在需要 replan 时携带当前 `observation_ref` 与有界可操作元素列表。慢脑优先选择语义匹配且唯一的句柄；不存在、不唯一或不可操作时才使用同次截图做视觉候选。

截图响应同时提供原始像素宽高。慢脑从缩放预览选择位置时，必须换算回原图像素并把同次 `observation_ref` 放入候选；预览尺寸未知或引用已更新时不显示为可执行视觉动作。任何层都不再追加 Retina backing-scale 换算。

## 状态与错误反馈

引用过期、Worker 重建、索引消失、截图尺寸变化、坐标越界或动作后状态未变化时，顶部只显示“界面已变化，需要重新观察”或“当前步骤待核实”，不得暴露元素文本或把失败步骤标为成功。

元素动作后的短暂 AX 延迟期间，顶部保持当前步骤“执行中”；有界只读 Observe 收敛一旦取得预期结构事实再显示成功。900ms 到期仍无证据时显示待核实并交回，不出现第二次点击步骤或重复动作动画。

协议 1.49 起，顶部当前 Driver 轮次与任务面板时间线显示有界原因，例如“Driver 动作超时，结果待核实”“Driver 拒绝动作”“Driver 已返回但效果未确认”“目标界面已变化”“Driver Observe 失败”或“Driver 连接失败”。文案不得拼接 SDK 原文、坐标、应用名、控件标签或消息正文。

同尺寸窗口的 transcript 已变化也按“界面已变化”处理。装饰性图像不单列为第二个动作候选；无可操作祖先的自绘图像若执行后没有出现计划要求的菜单、选中态或目标文本，顶部保持待核实并展示“重新观察/规划”，不得显示成功图标。

## 无障碍与平台验证

该扩展不新增依赖颜色、图像细节或精确指针操作的用户入口；顶部状态继续提供文字与图标双重反馈。macOS 以真实 Retina 显示器上的 Sky 应用截图验证原图坐标，Windows 原生证据按主人决定暂缓且不得由 macOS 结果外推。
