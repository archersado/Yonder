# DS-S1 产品需求

## 四状态运行时接线（2026-09-14用户优先实施）

子范围设计审阅通过，仅接入已有真实来源idle/executing/waiting_for_user/paused。RUN-ASSET-01执行切换完整左右摆爪帧；02等待/暂停立即打断执行，500/300ms入场后保持；03不可见、拖动和减少动态效果停止装饰序列；04任一素材加载失败回退旧透明形象，边缘双眼及hover菜单不退化。其余五态仍需真实事件来源，完整需求保留。眨眼沿用用户要求的3–5秒高频，覆盖原草案6–10秒。

- 透明小龙常驻、拖动、三分钟闲置靠最近屏幕边躲藏，忙碌或未知不隐藏。
- 平台限制与未实现项明确；涉及 UI/Driver/权限时分别提交 Windows/macOS 原生证据。

## 有任务才显示与忙碌形象（2026-09-14用户变更）

用户再次指出悬停未显示，并明确要求无任务不弹面板、有任务运行时显示忙碌动画。此处“有任务”定义为存在未结束任务（created/running/waiting-for-user/paused/interrupted）；已完成/失败/取消仍可从托盘历史查看，不触发自动悬停。来源为本次用户变更，映射DS-S2 AC2/AC5/AC6与DS-S1忙碌不隐藏要求。

验收：空库悬停不显示；有未结束任务悬停显示；同一悬停期间任务从无到有也显示；running或准入占用进入忙碌形象，结束后恢复闲置；等待/暂停仍能打开面板但不伪装正在执行；读取失败标记未知，不播放执行动画或作为收起许可。运行任务开始后已收起小龙唤醒；拖动不误开。减少动态效果只保留静态忙碌提示。

架构：TaskHost从既有TaskStore读取未结束列表limit1，复用activity()读取运行/准入事实；Rust返回两个派生布尔值，不新增持久化/任务状态所有者。专用本地pet命令固定窗口身份，在blocking worker查询SQLite；前端只保留瞬时表现。忙碌动画复用既有呼吸/尾巴/响应变换，加明显的“忙碌”提示，不生成新素材。原生悬停维持窗口内同坐标系检测，查询周期不作为严格性能门槛。

## 同桌面与面板操作（2026-09-14用户补充）

面板与小龙必须在同一桌面/Space，同进程应用相同原生窗口集合行为；不切换到其他Space打开。鼠标从小龙跨间隙进入面板后保持，面板上的现有任务按钮可操作；离开面板与小龙区域后隐藏，跨间隙留350毫秒宽限，已经进入面板后离开立即在下次原生观察隐藏。当前只读任务按钮仍为选择详情、刷新、分页，暂停/取消未接通不得假装执行。

小龙任务表现复用assets/mascot/互动动画生命周期-v1.md：真实执行占用映射executing（认真挥爪，约1.4秒循环），等待用户映射waiting_for_user，暂停/中断映射paused，其余idle。执行优先，非执行时首个未结束任务作为代表（按任务ID）；成功/失败一次性动画仍需真实事件去重，当前快照不重播。executing使用同角色透明四帧素材，不把整张PNG变换伪装成局部挥爪。此补充覆盖此前新增文字忙碌标记的工程建议。

## 2026-09-14 用户变更：九态专属循环

来源：用户“呼吸眨眼所有的状态都要有”“每个状态都要有自己的动作动画重复播放”。覆盖此前完成/失败单次、等待/暂停仅保持的视觉播放规则。状态退出立即打断，不重复发布事件或自动恢复任务。九态独立呼吸、3～5秒眨眼，并按状态循环：idle呼吸摇尾；listening抬身点头；thinking交替歪头、尾尖轻摆；executing短臂围绕肩部交替抬落；waiting_for_user举爪姿态轻点头；paused收翼姿态慢下沉放松回位；recording专注姿态慢摇尾；success轻跳落稳；failed低头后回看用户。暂停首版不反复展开翅膀。减少动态效果、拖动、隐藏停止装饰动作。

采用现有透明关键姿态与连续变换，不用全身交叉换帧模拟挥爪；不新增依赖、状态所有者或任务协议。四个真实来源状态沿用产品播放器，其余五态仅在独立预览模拟。验收逐态观察至少两轮动作、呼吸、完整闭眼再睁眼，执行爪根不断裂、背景无格子。浏览器证据不替代原生验收，Windows继续暂缓。


### 九态循环返工：专属动作必须可辨认

用户反馈除待命/执行外看不到动作，上一版仅整体轻晃不足以通过。撤回“九态动作通过”的产品结论。收到请求/等待响应改为头部独立抬动与左右歪头，身体固定；等待用户使用放爪到举爪的循环；暂停使用展开到收翼的循环；完成使用展翼举爪小跳；失败使用低头到回望；录制加强独立尾部慢摆。等待/暂停/完成/失败复用既有四帧关键姿态，来回播放并短暂停顿，避免直接从末帧跳回首帧。执行维持连续肩部抬爪，不恢复全身换帧。所有状态继续呼吸与独立眨眼。验收增加头部局部矩阵及多张姿态索引变化，不能只判断任意 transform 变化。局部分层原图保留，透明边缘与头颈接缝需目测验证。

失败状态帧混合在截图中出现重影，返回实施：改为单一回望姿态的头部局部分层，连续下移/俯转再回位；闭眼层使用相同矩阵，不混合两个完整头部。

用户追加“需要流畅的动画”：停止整图四帧混合用于状态动作。等待用户与成功提取单一举爪姿态的前臂，躯干仅在遮罩内补齐，前臂围绕肩部连续旋转；暂停保持收翼躯干，仅独立翼片围绕翼根连续俯转开合；成功跳跃连续缓冲。所有循环使用同一时钟与平滑正弦曲线，不重播事件，拖动/减少动态效果停止。验收要求躯干无整图交叉混合，动作局部矩阵连续变化，视觉接缝另行检查。


### 录制道具与动作语义（用户验收目标）

来源：用户要求准确表达状态，举例“录制这种可以拿出相机拍照闪光之类的，可以用道具来丰富动作”。录制改为双爪抱相机：低位准备、平滑举起、短暂停留拍照、局部低强度闪光、平滑放下，每轮4.8秒。相机与前爪共享运动锚点；红色录制指示稳定显示。闪光仅在镜头附近、每轮一次，不覆盖屏幕，不影响点击/拖动；减少动态效果保留静态相机与红点，不闪光。相机为独立透明位图，保留生成原图。

当前录制真实来源尚未接线，只在独立预览模拟；不得启动真实录制或调用拍照能力。验收需看到举起/放下、镜头附近闪光、连续呼吸眨眼，记录长周期和透明背景证据；用户满意尚未证明，不可用transform变化宣称完整目标通过。

等待状态返工：原生预览截图可见等待外部响应头颈接缝，等待用户持续摆爪像招手。头颈桥接区补齐并减小歪头角度；等待用户改成举爪停留后轻提示。分别使用小型省略点气泡（外部响应）与问号气泡（用户处理）明确语义，不表示Yonda在规划；保持循环、呼吸眨眼。提示不获取输入，不触发任务。用户具体问题尚待回复，此处先修已观察到的缺陷。

用户明确缺陷：等待用户前臂出现裁切痕迹、等待外部响应头部鳞片脱离。修复验收要求：头部遮罩包含完整侧鳞片；前臂遮罩完整覆盖前臂并柔化肩部接线，动作极值截图无切口、鳞片与头部同步。不能用提示气泡代替分层修复。

浅色背景极值检查发现尾部1像素分层线：所有状态现为单关键姿态连续动作，主图恢复普通alpha混合；尾片在零位移轴处增加1像素覆盖，避免两次裁切抗锯齿留下空隙。不恢复整图交叉混合。原图与动作语义不变。

减少动态效果验证修复：暂停态隐藏独立展开翼片，保留paused-03收翼主体；相机保留静态低位道具，闪光为0。ego浏览器仿真必须显式传media空字符串，否则不构成系统偏好证据。

状态辨识补充：暂停的收翼静态姿态仍可能被理解为普通站立，增加小型“Ⅱ”状态标记；收到请求增加小型“✓”确认标记；等待外部响应的三个省略点按顺序连续明暗流动。标记不承载任务详情、不接受点击；减少动态效果时保持静态，关闭明暗循环。


### 2026-09-15 撤销易开裂的局部分层

用户实机反馈：收到请求、失败状态头部裂开，等待用户手边有圆圈且需明确抬手，成功形象被切割。上述状态局部分层验收失败，撤销相关头/爪切片和圆形提示。收到请求、等待外部响应、等待用户、成功、失败均使用一张完整RGBA角色姿态作为主体，以连续整体位移/转动表达动作，杜绝头颈/手臂切口。等待用户固定使用完整举爪姿态，在该姿态上做轻柔抬身循环；不再显示问号圆圈。成功使用完整举爪展翼姿态做余弦小跳；失败使用完整低落姿态做缓慢下沉回位；收到请求使用完整抬头姿态做点头确认。保留呼吸和独立眨眼。旧局部素材保留为失败证据，不再由这些状态引用。

### 收到请求真实接线

来源：产品简报「桌宠」的 `listening` 标准状态与用户“动画准确表达 Yonda 状态”。验收 LISTEN-01：仅 Agent Gateway 成功接受 `task.create` 后显示约 1.6 秒；拒绝请求不显示。LISTEN-02：真实 executing 优先，不被收到请求覆盖。LISTEN-03：边缘休眠时收到真实请求唤醒；动画结束后回到 SQLite 派生状态。LISTEN-04：使用完整角色姿态、✓、呼吸和眨眼，不修改任务状态、不创建重复任务。

后续用户变更 WAKE-STATE-01：小龙已隐藏时，任一成功派生的展示状态变化都主动唤醒；状态查询从已知值变为不可用也唤醒并显示未知保护态。首次读取与相同值轮询不触发，避免启动或500ms查询造成重复窗口动作。

2026-09-16用户变更 EXEC-PRESENT-01：桌宠状态采用宿主事件驱动，不得周期轮询数据库。Yonder执行真实任务的整个动作调用期必须显示`executing`，不得因Gateway同步调用持有宿主锁而在动作结束后才刷新；开始事件立即唤醒并进入忙碌，调用结束事件回到SQLite/Admission派生状态。展示事件不得伪造完成、重试或资源释放，窗口首次加载只允许读取一次恢复快照。

### 终态一次性展示增量（2026-09-18）

来源为产品简报桌宠状态反馈、架构主干九态定义，以及本 Story 已记录的“成功/失败一次性动画需真实事件去重，当前快照不重播”。验收 TERM-PRESENT-01：只有统一 Gateway 的写请求真实提交终态后，才播放 `success` 或 `failed`；`task.get/list/events` 和启动快照不得触发。TERM-PRESENT-02：事件以 `task_id + sequence + status` 去重，播放约 1.8 秒后恢复同次响应后的 SQLite/Admission 派生状态。TERM-PRESENT-03：隐藏态收到新终态立即唤醒；重复事件不重播、不重复唤醒。TERM-PRESENT-04：协议拒绝、存储失败及非终态响应不播放终态动画。当前公开 Gateway 已有 `task.complete` 与 BUA `finish` 成功来源；失败终态仍只存在于 Application 的真实 `Outcome::Failed` 提交能力，本增量不为动画发明 `task.fail` 协议。
