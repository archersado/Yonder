# DS-S2 架构设计

## 边界与依赖

GUI子范围按AD-DS-01增量审阅进入Apply：apps/desktop复用已有Tauri2依赖与原生WebView；系统app_data_dir为真实任务库位置，不接受UI路径。task_query只允许本地task-space窗口，异步工作线程使用唯一TaskHost Mutex串行访问，超时/错误明确反馈。关闭仅隐藏窗口，托盘恢复。首批独立面板暂不迁移小龙，迁移与任务隐藏协调作为剩余原始AC，不能宣称已完成。

宿主核心子范围按AD-DS-01补充准入：apps/desktop库只依赖adapters/application。可信应用目录、进程持有标准文件锁、打开未加密SQLite、恢复至0、创建唯一Admission依次完成后才返回宿主。打开失败不交付可查询实例；本机查询身份固定desktop，不接受外部Agent/前端自报身份。宿主不开放任何传输，后续GUI绑定仍须窗口来源校验。类型及编码由Application转用既有protocol，禁止第二模型。

2026-09-14阶段修订：依Accepted AD-DS-01，研发接线不再以完整DS-S1完成为循环前提，改按本机基础证据与可信源/恢复条件逐项审阅。当前真实SQLCipher连接及本机身份尚未接通，产品Apply仍受该条件约束。禁止把正式总览追加到E0 Spike；后续桌面组合根遵守目标Workspace。

读取 TM 快照与 AG 派生协议，不持有核心状态；依赖 DS-S1、TM-S1、AG-S1。

## 状态与契约

2026-09-14后续存储决定：依Accepted AD-ST-01，本文SQLCipher前提被MVP未加密SQLite替代；当前表仍唯一事实源。密钥不再是接线依赖，可信身份、事务与恢复条件保留。加密和明文迁移归MVP之后ST-S2，不自动处理旧加密库。

契约联审结论见[DS-S2-CONTRACT-REVIEW](../DS-S2-CONTRACT-REVIEW.md)：首批仅复用既有TaskSnapshot四字段与ID游标；刷新重建当前页链。include_finished=true为全部，不是历史专用筛选；UI不自报可信身份。正式组合根与阶段准入未决前不得Apply。

2026-09-14细化：桌面组合根调用Application查询用例；Rust任务事实源与既有Rust派生协议继续唯一。UI只持当前页展示快照、选中任务与加载状态，不缓存第二套任务状态、不自行推进生命周期。列表、详情、控制动作分别依TM/AG既有契约；先检查真实字段及授权过滤，不为布局手写协议。

刷新采用调用方显式刷新及已有事件能力；断连/事件缺口时重新查询当前快照，不以历史事件重建事实源。查询失败保留旧快照并标记过期，禁止据此隐藏桌宠。外部浏览器引用由BU提供，打开调用已有系统/ego-lite入口，不引入内置浏览器。具体刷新机制与外部打开契约须在Proposal前完成联审，不新增轮询框架。

2026-09-18用户修订：按Accepted AD-BU-03显示只读引用摘要；Agent控制的活动引用可由可信本机命令调用ego-lite `handOff()`进入对应空间，Agent恢复时使用`takeOverTaskSpace()`。两者复用受监督Browser动作链并更新任务事实。

首个可实施子范围建议为真实只读列表与详情；前置为TM-S1/AG-S1可用查询授权及桌面阶段准入决策。DS-S1性能放宽仅解除性能阻断，尚未解决的正式宿主接线循环须先更新架构决策，不能用假数据绕过。TM-S3/S4/S5未就绪的控制/历史能力明确反馈未提供，完整原始需求保留。

SQLCipher 保持任务当前事实源；UI 仅持展示快照。传输类型从 Rust 派生。改变协议/持久化/边界前先补 ADR，不为本 Story 另建状态系统。

## 悬停入口变更（2026-09-14）

后续用户明确改为悬停小龙显示任务菜单，不再由点击打开。清醒小龙连续悬停200毫秒后显示贴身菜单；快速经过和开始拖动取消待打开。轻点仅动作反馈，休眠双眼轻点只唤醒。Enter/Space保留键盘菜单入口。悬停显示不请求原生焦点，当前应用可继续输入；进入菜单后可操作关闭，菜单失焦后隐藏。菜单不随离开小龙立即消失，以便跨越间隙进入菜单。

macOS 未激活 WKWebView 的悬停事件不能作为可靠唯一入口。复用Tauri原生cursor_position与窗口物理边界，以250毫秒有界串行查询补充悬停进入检测；只返回布尔值，不存储鼠标轨迹。仅可见清醒小龙检查，拖动按下时锁存已进入，避免拖动途中误开；无新增依赖或任务状态。

原生复验发现已安装Tao的全局cursor_position实现混用主屏像素高度和AppKit逻辑点；macOS改用既有NSWindow.mouseLocationOutsideOfEventStream与frame同坐标系判断，Windows保持Tauri物理坐标判断。无新增技术依赖。

## 有任务才显示与忙碌形象（2026-09-14用户变更）

用户再次指出悬停未显示，并明确要求无任务不弹面板、有任务运行时显示忙碌动画。此处“有任务”定义为存在未结束任务（created/running/waiting-for-user/paused/interrupted）；已完成/失败/取消仍可从托盘历史查看，不触发自动悬停。来源为本次用户变更，映射DS-S2 AC2/AC5/AC6与DS-S1忙碌不隐藏要求。

验收：空库悬停不显示；有未结束任务悬停显示；同一悬停期间任务从无到有也显示；running或准入占用进入忙碌形象，结束后恢复闲置；等待/暂停仍能打开面板但不伪装正在执行；读取失败标记未知，不播放执行动画或作为收起许可。运行任务开始后已收起小龙唤醒；拖动不误开。减少动态效果只保留静态忙碌提示。

架构：TaskHost从既有TaskStore读取未结束列表limit1，复用activity()读取运行/准入事实；Rust返回两个派生布尔值，不新增持久化/任务状态所有者。专用本地pet命令固定窗口身份，在blocking worker查询SQLite；前端只保留瞬时表现。忙碌动画复用既有呼吸/尾巴/响应变换，加明显的“忙碌”提示，不生成新素材。原生悬停维持窗口内同坐标系检测，查询周期不作为严格性能门槛。

## 同桌面与面板操作（2026-09-14用户补充）

面板与小龙必须在同一桌面/Space，同进程应用相同原生窗口集合行为；不切换到其他Space打开。鼠标从小龙跨间隙进入面板后保持，面板上的现有任务按钮可操作；离开面板与小龙区域后隐藏，跨间隙留350毫秒宽限，已经进入面板后离开立即在下次原生观察隐藏。当前只读任务按钮仍为选择详情、刷新、分页，暂停/取消未接通不得假装执行。

小龙任务表现复用assets/mascot/互动动画生命周期-v1.md：真实执行占用映射executing（认真挥爪，约1.4秒循环），等待用户映射waiting_for_user，暂停/中断映射paused，其余idle。执行优先，非执行时首个未结束任务作为代表（按任务ID）；成功/失败一次性动画仍需真实事件去重，当前快照不重播。executing使用同角色透明四帧素材，不把整张PNG变换伪装成局部挥爪。此补充覆盖此前新增文字忙碌标记的工程建议。

## 人工接管记录与交回（2026-09-14用户变更）

来源：本次用户明确执行中支持人工接管并记录用户行为，作为交回Agent的Observe依据；架构Recording与桌宠/任务恢复约束，Accepted AD-TM-03。仅Agent创建任务，人工接管不创建新任务。

验收映射：TAKE-01显式接管阻止Agent新动作，停止未确认不称已移交；TAKE-02本次手动接管开启可见、可停止的记录，只录user输入，密码/安全界面/排除应用不采；TAKE-03原始时间线不可变并关联原task_id；TAKE-04交回保存证据并执行新鲜Observe，向归属Agent交付轨迹/证据引用及当前状态；TAKE-05交接失败/配额缺口明确反馈、保持暂停，不自动续跑；TAKE-06Agent重新Observe并显式恢复，重新准入后才executing。

TM-S3管接管及停止确认，RC-S1管用户记录/不可变证据，TM-S5管任务时间线引用，TM-S4管交回及显式恢复，AG管归属Agent交接协议，DS-S2展示已有任务接管/记录中/交回。自动输入干预只暂停，不无提示开启Recording；显式接管作为用户手动开始。已有每设备Recording时明确冲突，不覆盖。

UI流程：任务面板“接管”→“正在停止Agent控制/记录中”→停止确认后人工控制；小龙按既有暂停表现并保留独立录制提示。用户可以停止记录，任务仍保持人工接管；交回时如果停止后有未记录操作标注证据缺口，最终Observe仍必须新采集。“交回Agent”不等于立即继续，不用点击桌宠自动恢复任务。

协议/持久化/Driver停止与授权/隐私字段未定稿，相关Story保持设计阶段，不提前实现采集或向外发送用户记录。Windows暂缓、真实双平台证据保留。

## 任务卡片操作（2026-09-14用户变更）

来源：用户明确任务上应有接管、删除等按钮，产品简报Task Space与权限模型、AD-TM-03/04。操作直接放在各任务卡片底部，详情选择按钮与操作按钮为兄弟元素，禁止嵌套button。created提供取消任务；接管只适用于真实执行中的任务，目前停止/Recording前置未接，禁用并说明原因，不伪报已接管。删除语义按本次用户澄清或明确默认设计定稿后实施；首批准备期间禁用并说明。已有Agent专属创建、hover面板同桌面/移出隐藏保持原验收。

验收CARD-01每卡片显示接管/取消/删除三个名称明确按钮；CARD-02取消created复用同一Application且目标隔离，终态禁用取消；CARD-03未满足接管/删除门禁不发控制请求，错误与不可用可见；CARD-04按钮支持键盘焦点、互不触发详情选择、提交防重复。删除持久化/协议变化须先Architecture Decision与相关Story设计，不只从UI删除DOM。

删除已按Accepted AD-TM-05定稿，由TM-S5实现；终态显示可用删除按钮，用户确认清理历史且保留防重放标记才发送task.delete，活动任务禁用并提示先取消/停止，取消确认不发请求。

## 当前生效规格覆盖

用户明确删除只取消、任务数据不删除。Accepted AD-TM-06覆盖此前AD-TM-05段落，卡片统一为接管/取消任务，避免重复同义按钮。取消保留说明/事件/Outbox/幂等，全部可查。接管适用执行中但停止/记录前置未实现禁用并说明；created取消可用、执行过或终态暂禁用，不发清理请求。

## 工作定位原生路线审阅输入（2026-09-14）
