# EX-S1 架构设计

## 边界与依赖

使用隔离样本和一次性探针，不接产品 Gateway/SQLite，不复制参考项目 Python Agent 或浏览器引擎。固定相同计划、授权、观察输入、设备与任务目标；对照 A 为慢脑每步决策，B 为 Jev 在动态候选中选操作/目标。样本覆盖 CUA（可访问控件与失效控件）、BUA（ego-lite 可见控件与导航失效）、Document（有/无完整编辑参数）、Command（安全只读程序与参数缺失）；每类有成功/失败输入。敏感操作只验证拒绝/确认闸，不产生真实副作用。

## 状态与契约

在调用 Jev 前冻结样本版本、成功判据、失败注入、置信阈值及测量脚本。至少对照任务成功率、误操作、慢脑总输入/输出 token、Jev 次数与费用、端到端时延、交回率、取消至停止新动作耗时；以同一批重复运行报告分布与失败，不将单次演示当统计证明。若出现权限绕过、`unknown` 自动重试、旧目标动作、`DONE` 无独立验证，立即淘汰该路线；若 token 无可重复收益或质量低于基线，则不进入产品 Story。具体数值门槛在 Spike Change 创建前定稿。

## 失败与验证

核实 TypeSafe 官方 API 及许可、输出结构、置信校准、数据传输与留存、费用、网络故障。Jev 若为远端服务，探针只发送最小脱敏候选摘要；正式 Connector 须另经架构审阅。Windows/macOS 用同一行为样本，不要求相同底层控件 API；Windows 暂缓期间只记录未验证。Spike 结束形成可复现原始计数、失败分类、候选操作覆盖表及 AD-EX-02 接受/淘汰/缩小范围结论。
