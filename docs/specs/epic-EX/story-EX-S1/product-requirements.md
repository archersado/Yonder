# EX-S1 产品需求

## 问题与目标

原始需求：产品简报「产品定义」第 2、3 项、「MVP 主干链路」第 5～9 项、「两条执行路径」要求 Agent 驱动、有控制的观察与执行；补充材料「执行原则」要求模型无关 Driver。后续用户变更（2026-09-21）：Jev 在各 Driver 上方作快脑，外部慢脑负责初始规划和 Observe 后 replan，两类慢脑输入沿用现有 Gateway，追求较少 token 与较高质量。架构约束：Accepted AD-EX-01 已允许有界内置模型循环；具体 Jev 技术接入仍须双平台 Spike 和 AD-EX-02。参考实现 [browser-use/jev-ultrafast](https://github.com/browser-use/jev-ultrafast) 只提供动态候选、目标新鲜度和文本助手分工的验证思路，不是产品要求。

## 范围与非目标

本 Story 只验证技术路线，不接真实用户任务、不持久化内容、不引入长期双栈。时间盒：至 2026-10-05；Windows 按用户现行决定暂缓时可完成 macOS 子范围，但 ADR 不能因此 Accepted。

## 验收条件

| ID | 对应来源 | 验收 |
|---|---|---|
| EX1-01 | 用户变更；补充「执行原则」 | 固定同一组 CUA、BUA、Document、Command 隔离任务，列出每次 Observe 可枚举的操作/目标、缺参场景和交回率；至少覆盖各执行层一条成功及一条失败路径。 |
| EX1-02 | 用户变更「降低 token、提升质量」 | 与慢脑逐步决策基线同条件对照，事先冻结成功率、误动作、慢脑 token、端到端时延、成本及中断响应门槛；原始计量边界可复现。 |
| EX1-03 | 架构「每步 Observe」「unknown」 | 旧目标、低置信、权限不足、模型超时、用户中断、`unknown` 均不派发新副作用；`DONE` 由独立 Observe 校验。 |
| EX1-04 | 双平台围栏 | Windows/macOS 使用同一任务与判定口径，保留结构化证据、淘汰原因及 AD-EX-02；单平台不得通过。 |

## 待审建议

数值门槛、候选上限、置信阈值和 Jev 运行位置均由 Spike 方案在运行前冻结，不能从演示结果倒填。若自由文本、命令或文档修改每步仍要慢脑生成，则报告不适用范围，不宣称整体 token 收益。
