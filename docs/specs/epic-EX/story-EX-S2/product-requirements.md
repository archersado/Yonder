# EX-S2 产品需求

## 问题与目标

原始需求：产品简报「MVP 主干链路」第 5～9 项及「Task Space 与权限模型」要求 Agent 发起、用户可见可控、逐任务审计；补充材料「CUA 与 BUA 的 Task Space」规定两条路径共享任务与权限。后续用户变更（2026-09-21）要求外部慢脑首规/Observe 后 replan，Jev 快脑选择执行动作，并明确慢脑链路仍从现有 Gateway 进入。2026-09-22 用户变更要求 Jev 支持配置界面。架构约束：架构主干「Agent Gateway」「任务、状态与恢复」及 AD-TM-08/13 的任务身份、动作后 Observe、同事务事件/Outbox、单租约与 `unknown`。本 Story 不改变首次计划和 replan 的外部所有权。

## 范围与非目标

范围是已验证计划片段内的本地决策、执行与交回；非目标是外部 Agent 首次计划、语义 replan、第二 Gateway 或第二任务状态机。

## 验收条件

| ID | 对应来源 | 验收 |
|---|---|---|
| EX2-01 | 用户变更 | 外部 Agent 以任务身份提交有期限、能力范围、预算和版本的计划片段；无计划、过期或版本不符拒绝快脑派发。 |
| EX2-02 | 原始任务/权限需求 | 每个快脑选择只作用于已授权任务和既有步骤/attempt；策略、确认、租约、同文件写锁不能被模型输出绕开。 |
| EX2-03 | 架构 Observe/恢复 | 每个动作后 Observe；进展可继续，偏离/低置信/缺参/预算耗尽交回慢脑；`unknown` 冻结并由慢脑在新鲜 Observe 后决策，不自动重试。 |
| EX2-04 | 原始可见可控 | Task Space 可看见当前是「本地快脑执行」「等待慢脑重新规划」「等待用户」及对应最小原因；取消/接管立即冻结后续决策。 |
| EX2-05 | 双平台围栏 | 协议合约、状态/Outbox 集成及 Windows/macOS 原生证据通过独立 Verification Goal。 |
| EX2-06 | 用户 Gateway 链路要求 | 本地/云端慢脑的首次计划、replan 均经现有 Agent Gateway 入站；交回依据由任务事件/Outbox 向归属 Agent 提供，拒绝其他 Agent 或绕过 Gateway 的计划更新。 |
| EX2-07 | AD-EX-01；AG-S3/TM-S2 既有契约 | 快脑可在已验证计划内连续推进步骤，但使用可信内部来源并保留归属 Agent；不能伪造 Agent 会话调用 Gateway，`DONE` 不能直接提交任务 completed/failed。 |
| EX2-08 | 2026-09-22 用户变更；原始可见可控 | 从系统托盘菜单打开独立最小 Jev 配置窗口：启用/关闭、已定稿服务形态与端点、每片段步数/时间/token 上限、允许的执行层上限；保存前校验，无效配置不得派发快脑。置信阈值和敏感操作闸只读展示，不允许用户降低；配置区不嵌入 Task Space。 |
| EX2-09 | 配置持久化与安全 | 非敏感配置由 Application 保存并校验；保存成功不代表模型可用。API Key、证书、刷新令牌和完整端点查询串不得进入该配置或界面日志。 |

## 待审建议

计划片段最小字段、步数/时间/token 预算和低置信阈值在 EX-S1 之后定稿；用户配置只是全局上限，实际片段始终取计划授权值与全局上限的较小值。首版不在界面保存 API Key、模型自由文本、命令参数或候选规则；远端认证与凭据存储必须等 AD-EX-02 与 ST-S2 定稿。首版不设计通用工作流语言或第二套任务状态机。
