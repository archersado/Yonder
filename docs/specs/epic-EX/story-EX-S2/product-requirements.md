# EX-S2 产品需求

## 问题与目标

原始需求：产品简报「MVP 主干链路」第 5～9 项及「Task Space 与权限模型」要求 Agent 发起、用户可见可控、逐任务审计；补充材料「CUA 与 BUA 的 Task Space」规定两条路径共享任务与权限。后续用户变更（2026-09-21）要求外部慢脑首规/Observe 后 replan，Jev 快脑选择执行动作，并明确慢脑链路仍从现有 Gateway 进入。2026-09-22 用户变更要求 Jev 支持配置界面。架构约束：架构主干「Agent Gateway」「任务、状态与恢复」及 AD-TM-08/13 的任务身份、动作后 Observe、同事务事件/Outbox、单租约与 `unknown`。本 Story 不改变首次计划和 replan 的外部所有权。

## 范围与非目标

范围是已验证计划片段内的本地决策、执行与交回；非目标是外部 Agent 首次计划、语义 replan、第二 Gateway 或第二任务状态机。

## 验收条件

| ID | 对应来源 | 验收 |
|---|---|---|
| EX2-01 | 用户变更 | 外部 Agent 以任务身份提交有期限、能力范围、预算和版本的计划片段；无计划、过期或版本不符拒绝快脑派发。 |
| EX2-02 | 原始任务/权限需求 | 每个快脑选择只作用于已授权任务和既有步骤/attempt；策略、确认、租约、同文件写锁不能被模型输出绕开。 |
| EX2-03 | 架构 Observe/恢复 | 每个动作后 Observe；进展可继续，偏离/低置信/缺参/预算耗尽交回慢脑；`unknown` 冻结并由慢脑在新鲜 Observe 后决策，不自动重试。 |
| EX2-04 | 原始可见可控 | Task Space 可看见当前是「本地快脑执行」「等待慢脑重新规划」「等待用户」及对应最小原因；取消/接管立即冻结后续决策。 |
| EX2-05 | 平台围栏 | 受限 macOS CUA 基线须通过协议合约、状态/Outbox 集成及 macOS 原生证据；Windows 证据仍作为 Story 完整 Done 的待办，不得误标完成。 |
| EX2-06 | 用户 Gateway 链路要求 | 本地/云端慢脑的首次计划、replan 均经现有 Agent Gateway 入站；交回依据由任务事件/Outbox 向归属 Agent 提供，拒绝其他 Agent 或绕过 Gateway 的计划更新。 |
| EX2-07 | AD-EX-01；AG-S3/TM-S2 既有契约 | 快脑可在已验证计划内连续推进步骤，但使用可信内部来源并保留归属 Agent；不能伪造 Agent 会话调用 Gateway，`DONE` 不能直接提交任务 completed/failed。 |
| EX2-08 | 2026-09-22 用户变更；原始可见可控 | 从系统托盘菜单打开独立最小 Jev 配置窗口：启用/关闭、已定稿服务形态与端点、每片段步数/时间/token 上限、允许的执行层上限；保存前校验，无效配置不得派发快脑。置信阈值和敏感操作闸只读展示，不允许用户降低；配置区不嵌入 Task Space。 |
| EX2-09 | 配置持久化与安全 | 非敏感配置由 Application 保存并校验；保存成功不代表模型可用。API Key、证书、刷新令牌、完整端点查询串和 URL 内嵌凭据不得进入该配置或界面日志；远端端点必须使用 HTTPS。 |
| EX2-10 | AD-EX-04 Proposed 边界 | 在 AD-EX-04 转为 Accepted 前，本 Story 只实现当前“每步 Jev 决策”基线，不引入 Recipe、批处理执行或可执行 DSL。 |
| EX2-11 | 运行中配置快照 | 配置在片段开始时形成快照，片段运行中不得热替换；关闭 Jev 后必须立即停止下一次决策并交回慢脑。 |
| EX2-12 | 2026-09-24 用户变更；AD-EX-02 | macOS 先接入远端 Jev 决策，Windows 后补；API Key 仅从 macOS 系统凭据入口读取，服务名 `Yonder`、账号名 `jev`，不得进入配置、SQLite、任务数据或日志。 |
| EX2-13 | 2026-09-24 用户变更；AD-EX-02/03 | 用户可在独立设置面板输入 API Key；提交仅写入 macOS Keychain，页面只显示是否已配置，绝不回显或导出既有密钥。 |
| EX2-14 | 2026-09-28 用户变更；AD-AG-09 修订 | CUA 计划候选必须包含受限动作语义、最小前置 Observe 条件和动作后预期条件，Jev 不得仅凭候选 ID/布尔值选择；不一致即交回。 |
| EX2-15 | 2026-09-28 用户变更；执行安全约束 | 涉及发送的 CUA 候选只能引用本地一次性确认；接收人和正文不得进入计划片段、Jev 请求、日志或 Outbox。用户确认后由 Driver 以短暂内存参数执行，Observe 必须证明发送结果。 |
| EX2-16 | 2026-09-28 用户变更；快慢脑职责修订 | 慢脑一次提交的有界片段可由单次 Gateway 执行调用连续推进；每动作后仍强制 Observe，并在下一副作用前复核用户控制和当前事实。成功路径不得要求慢脑逐槽位续调；异常立即停止并交回。 |
| EX2-17 | 2026-09-28 完整产品链路要求；TM-S8 | 安装包内 `yonder mcp` 必须导出计划片段提交与执行工具，使真实 Codex 慢脑可以从产品入口驱动 Jev 快脑；只在线协议/Gateway 存在但 MCP 不可调用视为未完成。 |
| EX2-18 | 2026-09-29 用户变更；AG-S5/TM-S8 | 异常交回提交后须经既有双向Agent输入通道主动唤醒唯一的归属慢脑会话；慢脑重新读取事实并经原Gateway提交replan。未连接或投递失败必须明确显示，不能让任务伪装成仍在执行，也不能由Yonder本地生成语义计划。 |

## 待审建议

计划片段最小字段、步数/时间/token 预算和低置信阈值在 EX-S1 之后定稿；用户配置只是全局上限，实际片段始终取计划授权值与全局上限的较小值。首版不在界面或 Jev 配置中持久化 API Key、模型自由文本、命令参数或候选规则；面板非空输入只直写 macOS 系统凭据入口，Windows 后补。首版不设计通用工作流语言或第二套任务状态机。
