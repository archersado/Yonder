# EX-S5 产品需求

## 问题与目标

- 原始需求：产品简报「MVP 主干链路」要求 Agent 基于任务事实持续执行并可审计；补充材料「执行原则」要求 Observe 后再决策。
- 后续用户变更（2026-10-09）：已经验证成功的执行路径应指导后续任务；发生 replan 时应先召回，再让慢脑规划。
- 架构约束：ARCHITECTURE-SPINE「Agent Gateway」「任务、状态与恢复」、AD-EX-01、AD-EX-05、AD-TM-23、AD-TM-24；慢脑仍拥有语义规划，活动任务仍由事件驱动 Runtime 拥有。

## 验收条件

| ID | 来源 | 验收 |
|---|---|---|
| EX5-01 | 用户变更 | handback 唤醒慢脑前，以当前动作的稳定、非敏感特征召回最多三条经验提示，并与任务 ID、序号和原因一起交给唯一归属慢脑。 |
| EX5-02 | Observe/核验约束 | 只有 Driver 后置 Observe 已确认且任务目标由归属慢脑核验 achieved 的样本可晋升为成功经验；`unknown`、待核实或仅有动作回执不得晋升。 |
| EX5-03 | 隐私与安全 | 经验不得包含任务正文、用户输入、消息正文、联系人、截图、transcript、坐标、PID/window ID、元素索引、Observation 引用或完整 Agent/模型 Payload。 |
| EX5-04 | 慢脑边界 | 召回仅提供建议性策略、前置条件和成功条件；慢脑必须重新读取 Gateway 新鲜事实，经验不得直接生成计划、执行动作、提升任务状态或绕过确认。 |
| EX5-05 | 轻量运行时 | 召回使用本地精确索引与有界排序，不使用向量库；无记录、存储忙、超时或错误时立即按原链路唤醒慢脑，不阻塞执行和 handback。 |
| EX5-06 | 可观察性 | 顶部浮窗只显示“已召回执行经验/无可用经验，慢脑重新规划”，不展示正文、模型原文、置信思维链或经验库内容。 |

## 范围与非目标

首版覆盖 CUA 计划片段的动作类型、应用标识、控件角色、交互方式和验证条件。敏感发送动作只允许召回“仍需用户确认”等安全围栏，不记录目标或正文，也不允许经验触发发送。BUA、Document、Command 后续须分别补充可验证的稳定特征后才能写入经验。
