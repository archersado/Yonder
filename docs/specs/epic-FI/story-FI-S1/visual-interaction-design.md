# FI-S1 视觉交互设计

## 入口与流程

默认另存；覆盖与删除需可信本地确认，Agent字段不能自报确认。冲突明确区分路径越界、同文件占用、Office/WPS锁定、目标已存在和提交未知；用户文件不在自动验证中被修改。

## 状态与错误反馈

呈现真实可观察状态；加载、等待、失败和未提供能力不能伪装为完成。无独立界面时由调用方界面或结构化响应承载，不额外建立窗口。

## 无障碍与平台验证

有 UI 的按钮提供名称与可见焦点，支持键盘，减少动态效果遵循系统偏好；无 UI 时保证调用错误稳定可区分。原生交互须各平台独立证据。

## 待决事项

本增量没有 Agent 或用户文件选择入口。内部调用方区分路径越界、文件过大、目标已存在、身份/内容变化、Yonder 占用、宿主锁定、校验失败、提交未知与平台不可用。只有后续可信本机 UI 才能调用回收站；Agent 请求不得出现可伪造的“已确认”布尔值。

授权核心本轮仍不新增 UI。后续原生选择器签发时，界面必须显示任务、归属 Agent、读取/新建/替换/回收站用途和短期有效提示；不得向 Agent 或错误日志展示授权根之外的信息。到期、撤销、用途不符和一次性引用已消费分别提供稳定反馈，不能自动重新弹窗或静默扩大范围。

## macOS Runtime 调用反馈

读取成功只返回有界内容、身份和哈希，不写日志。写入在原子提交前不得显示成功；同步结果不明显示“结果待核实”，不自动重试。回收站成功必须确认原路径消失且系统返回的新位置存在；失败保持原文件并给出稳定分类。
