# RC-S2 产品需求

## 问题与目标

用户希望把一次明确录制的桌面操作整理成可读、可修改、可重复使用的流程，在回放前核对步骤，并能随时停止。Yonder需要复用示教结果帮助Agent执行，不建立脆弱的绝对坐标宏系统。

## 范围与非目标

### 范围

- 从RC-S1已停止且完整性可判定的不可变时间线派生版本化Trajectory。
- 把连续事件整理为点击、双击、拖动、滚动、快捷键和文本输入等可审阅步骤。
- 用户可删除、调整顺序、编辑允许的参数、命名并保存一个派生版本；原始时间线不变。
- 回放前展示步骤、目标、参数缺口和风险，经过确认后由Agent创建任务并调用Yonder回放。
- 回放复用CUA Driver、单前台租约、每步Observe和用户输入立即暂停。

### 非目标

- 不复制参考插件的`rpatap`、CGEvent绝对坐标执行器、固定延时回放或第二套技能运行时。
- 不自动把任意Recording泛化为参数化流程，不用模型猜测步骤语义。
- 不记录或回放密码框、系统安全界面、用户排除应用及来源不可信事件。
- 不由用户界面伪造Agent身份或直接创建任务。
- 不在输入正文持久化决策完成前保存原始按键正文。

## 验收条件

- RC2-01：只接受RC-S1已停止的记录；存在`gap`、`excluded`或`external_unknown`时清楚标记，默认不能生成“完整可回放”结论。
- RC2-02：原始时间线不可修改；每次编辑生成有版本号的新Trajectory，保留来源`recording_id`和前一版本引用。
- RC2-03：事件折叠规则确定、可复现且有界；无法可靠归并的事件保留为待处理项，不静默丢弃或猜测。
- RC2-04：每个动作包含目标应用/窗口匹配、动作类型、AX目标、窗口内相对坐标回退、参数、预期结果和Observe策略；绝对屏幕坐标不能作为唯一目标。
- RC2-05：密码、安全输入、隐私排除和来源不可信事件不生成可回放动作；截图与输入正文不进入普通日志。
- RC2-06：审阅界面支持删除、排序和编辑允许参数；修改后重新校验动作、目标、依赖和风险。
- RC2-07：文本输入默认显示为待补参数或脱敏摘要；保存字面正文必须等待独立数据安全决策，当前不得隐式落盘。
- RC2-08：用户选择回放后，已连接Agent创建并命名任务；Yonder取得唯一桌面租约后才显示倒计时和执行状态。
- RC2-09：回放每一步都经CUA执行并Observe；预期不满足、目标失效、权限变化、用户输入或超时立即暂停，不自动跳过或重试副作用未知动作。
- RC2-10：倒计时和执行期间提供始终可见的停止入口；Esc、任务卡片暂停/取消和真实用户输入按统一控制语义处理。
- RC2-11：回放产生的输入标记为`replay`，只进入审计，不被RC-S1再次录制。
- RC2-12：Windows/macOS使用同一套Word/WPS、浏览器和文件管理器样本验证录制派生、目标重定位、逐步Observe、暂停与恢复；单平台通过不算Story完成。
- RC2-13：流程库支持查看版本、复制为新版本和删除派生流程；删除不改写原始Recording或已发生的任务审计。

## 与RC-S1的分工

RC-S1负责可靠采集、来源分类、隐私排除、不可变原始时间线和停止边界；RC-S2从已提交时间线派生、审阅、版本化并请求安全回放。RC-S2不得为了回放方便降低RC-S1来源门禁。
