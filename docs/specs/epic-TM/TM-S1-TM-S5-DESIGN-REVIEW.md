# TM-S1 / TM-S5 联合设计复核

性质：设计阶段复核，不是独立实施 Verification Goal，不作为 Story Done 证据。依据产品简报「Task Space 与权限模型」「MVP 主干链路 9」、补充材料「CUA 与 BUA 的 Task Space」和架构主干「任务、状态与恢复」「个人上下文」。ADR 为 AD-TM-01（Proposed）。

## 本轮关闭的职责问题

- 最新状态和历史事实职责明确，但共享事务和序号，不另建任务库。
- 不能仅保留最新详情；历史字段通知不足以实现审计。
- 不能用一个任意元数据入口混合 Agent 声明、Driver 事实和用户确认。
- 不把数据库事务扩展解释为文件/桌面副作用可回滚。
- 同一摘要的两次真实观察不等于重复投递；幂等不是按文本去重。
- 终态后可记录用户确认而不改执行终态；“终态不可再执行”不意味着禁止审计。
- 已定义 task_id/step_id/attempt_id/request_id/sequence 的职责，不重复引入同义 action_id。
- 已列明可信作者与状态允许矩阵：新的动作/意图受执行状态限制，可信迟到事实与用户确认不等于新执行。
- 已明确任务内提交去重与创建幂等的区别：重投递返回原结果，换 request_id 不能覆盖同尝试终结结论。

## 设计场景走查

| 场景 | 应保持的不变量 | 对应验收 |
|---|---|---|
| 步骤 A 观察后开始 B | A 的事实保留，B 不继承 A 成功结论 | TM1-AC10/16、TM5-AC01 |
| B 已开始，A 的执行结果迟到 | 不覆盖 B，绑定原 attempt_id；未知尝试或伪造作者拒绝，合法补充只进历史 | TM1-AC15/16 |
| 终态与步骤声明同时提交 | CAS 决定顺序，终态后无新的待执行意图 | TM1-AC02/08 |
| 写产物引用/事件/Outbox 中途失败 | 数据库内部整体回滚，不能提前发布成功 | TM1-AC03/16、TM5-AC07 |
| 文件已生成，但任务事务失败 | 不重做动作、不删除用户文件，保留待核实 | TM1-AC15、TM5-AC05/07 |
| 任务完成后用户确认，再次投递同请求 | 执行终态不变，确认不重复；须核验当前授权 | TM5-AC04/06 |
| 收到事件 n，get 返回 n+1 | 标记最新详情，历史 n 从历史事实读取 | TM1-AC07、TM5-AC01/08 |
| 保留策略清理历史附件 | 不伪装完整历史或有效引用；未同步/固定数据不得自动删 | TM5-AC05/08 |

以上仅为设计检查，未运行新数据库/Driver 测试。

## 本轮新增走查

| 场景 | 预期设计行为 |
|---|---|
| 客户端超时后复用 request_id 重投递 | 校验当前权限后返回同一次已提交结果，不新增事件/attempt |
| 相同 request_id 改操作或改内容 | 冲突；不能用旧回执确认另一项操作 |
| 值相同但两次真实观察 | 各自保留事实，不能按摘要内容去重 |
| 返回原 sequence 的回执时 UI 已见更大序号 | 回执只确认原操作，不能回退 UI 最新状态 |
| 完成后可信执行器补报旧尝试结果 | 关联原 attempt，只补审计，不修改任务终态或当前步骤 |
| 未知/复用 attempt_id 上报成功 | 拒绝，不允许请求自称执行器证明 |
| 撤销 Agent 权限后旧动作停止 | 新动作/读取拒绝，宿主仍处理可信停止事实；不因此启动额外 Observe |
| unknown 后出现新证据 | 保留 unknown 与后续证据的关联，不改旧事件，不自动恢复或完成任务 |

## 进入 Proposal 前仍须关闭

1. 标识职责、作者/状态矩阵本轮已明确；具体观察子操作字段和终结结果结构随 payload 定稿，不再重新扩展标识层次。
2. 本轮已列出创建/状态/声明/尝试/结果/Observe/控制/产物/确认/补充的最小事实及受控引用；8 KiB 事件、256 KiB 完整响应是待整体 ADR 审阅的工程限额，具体错误/控制枚举随对应 Story 定稿。
3. 本轮已明确附件/审计/用户产物的保留区别、去重随任务保留和版本化清单；总配额、清理记录实现、远端删除协议与最小防重放标记的隐私/格式仍需跨模块定案。
4. 定案 AG 的作者/当前授权校验、幂等语义及查询投影；存储/协议版本和旧库迁移单独评估。
5. 明确 AC11 全量忙碌/未知查询，与瞬态执行占用和当前状态的关系。

三份 Story 设计与 ADR 关闭这些事项前，状态保持 design-review，不创建功能实施 Proposal。密钥、桌宠菜单继续暂停。

## 2026-09-12：事件内容与预算走查

| 边界 | 设计处理 | 对应验收 |
|---|---|---|
| 字段字节各自合规，但 JSON 转义后超 8 KiB | 拒绝普通声明或由可信结果用例提供有界核心事实与就绪引用；不直接截断正文 | TM1-AC03/10、TM5-AC07 |
| 请求 100 条且单条接近 8 KiB | 按 256 KiB 整响应预算提前返回；不能承诺总会返回 100 条 | TM1-AC07、TM5-AC08 |
| 下一事件放不下 | 留到下一页，游标只到最后已返回序号；不跳项 | TM5-AC08 |
| 第一条历史事件本身超限/损坏 | 明确错误，不返回空页加 has_more=true | TM5-AC08 |
| 一次结果超过 16 个产物 | 引用完整、稳定、有版本的分页清单；缺少清单不能声称完整结果 | TM5-AC05/07 |
| 引用有效但当前权限已撤销 | 拒绝解析；不因为知道 reference_id 而恢复访问 | TM1-AC12、TM5-AC06 |
| 同一路径内容后来变化 | 保留产出时版本依据，报告改变/不可核实，不沿用旧确认 | TM1-AC13、TM5-AC04/05 |
| Observe 请求重复，或确实进行第二次 Observe | 前者复用 attempt/observe_index，后者必须登记新轮次；不上报即视为未观察 | TM5-AC01/03 |

这些是文档场景检查，尚未运行序列化边界测试。正式 Proposal 需把字节转义、包络、游标、首项超限和清单完整性转换为真实 Rust/Adapter 合约测试。限额不代表当前代码已有相同处理。

## 2026-09-12：保留、删除与防重放走查

| 场景 | 设计处理 | 需求依据 |
|---|---|---|
| 任务证据附件超过 7 天但未同步/已固定 | 保留，不自动删；同步未知也保留 | 架构保留期限与 AGENTS 保护条件 |
| 一个任务结束，另一任务仍使用同附件 | 按全部引用判断保护，不由单任务结束触发删除 | 资源引用与多任务隔离 |
| 用户输出文件超过 7 天 | 任务清理不碰用户文件 | 原应用资源所有权、受控文件删除 |
| 证据到期后查询旧事件 | 事件存在，引用明确过期；不产生伪造的历史缺口 | 时间线与审计可检查 |
| 删除本地历史但远端未确认 | 本地拒绝读取，显示远端清理未确认，不继续发送旧正文 | 客户端同步与删除关联清理 |
| 物理附件清理中进程退出 | 保留持久化清理状态；不先报告空间已释放 | 外部副作用不能假装事务回滚 |
| 附件过期后重投递原请求 | 保留原提交事实及失效引用，不重新执行 | unknown 不自动重试、幂等 |
| 删除任务后重复创建/写入同 task_id | 最小防重放标记阻止复用，不保留已删正文回执 | 去重和删除隐私边界的工程设计 |
| 清单发布后新增产物/原文件改变 | 新版本或失效状态，不篡改旧清单/旧确认 | 产物审阅与版本关联 |
| 总配额不足 | 限制新创建/派发，不清理未同步或固定数据 | 有界队列、本地配额和不写满磁盘 |

以上无真实文件删除、同步或清理测试。保留审计无自动 TTL、附件计时起点、最小防重放标记属于设计选择，仍待整体 ADR 审阅，不冒充产品原文。
