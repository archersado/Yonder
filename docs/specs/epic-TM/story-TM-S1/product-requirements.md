# TM-S1 产品需求

## 问题与目标

用户并行运行多个任务时，需要知道哪些正在执行、哪些需要自己处理、哪些已经结束；Agent 和桌面必须读取同一事实源。应用重启后不能悄悄重做尚未确认结果的动作。

本 Story 交付可信内部任务记录、归属、状态迁移、列表、逐任务事件和恢复用例。创建只表示记录存在，不等于动作已派发。

## 范围与非目标

TM-S1 负责状态事实源，AG-S1 负责认证与外部接入，DS-S2 负责展示，TM-S2 负责执行资源，TM-S3/S4 负责控制和继续。各模块不得各存一套任务事实。

不包含 Socket/CLI/MCP、窗口布局、真实执行器、自动规划与动作重试。本轮保留既有加密存储，不恢复密钥开发，不迁移用户旧库。完整任务可见仍要求名称、来源、当前步骤和观察摘要，不能通过缩小范围把这些未完成需求删除。

### Agent 等待用户首批增量（2026-09-18）

来源：产品简报“桌宠展示等待用户介入”、TM1-AC14 与架构主干“持久化等待原因”。归属 Agent 仅可在真实动作已 Observe 并推进到安全步骤边界后，将 running 任务置为 waiting-for-user；原因随状态事件与 Outbox 同事务保存并可查询。未停止、unknown、存在待处理控制、旧序号和越权请求必须拒绝且不释放资源。本增量不提供 Resume，用户回答与恢复仍由 AG-S5/TM-S4 后续闭环。

## 主流程

可信宿主创建记录 → TM-S2 准入并提交 running → 用户/Agent 同源查询 → 按 task_id/sequence 补读变化 → 确认结果后进入历史。重启时单实例宿主先完成恢复再开放执行；之后重新 Observe，由外部 Agent 显式决定下一步。

## 待决事项

保留场景补充到 AC07/12/13/16：附件过期不删除状态事件、不允许原提交重放；历史删除不能复用 task_id 创建另一动作，也不能继续投递已删正文。保留无正文标记、审计无自动 TTL 是待审工程方案，不改变用户对显式删除的确认要求。远端未确认删除必须如实可见。

2026-09-12 验收细化：AC05/07 的有界分页允许因字节预算少于请求条数，但不能漏项；AC10 的超限声明明确拒绝，不静默截断；AC13/16 的大量产物通过完整版本清单访问，不牺牲原需求的可检查性。8 KiB/256 KiB 和 16 引用为工程限额建议，不来自产品原文。

本轮验收细化：AC02/07 验证原提交回执不回退新快照；AC12 验证权限撤销后不凭去重结果恢复读取；AC15/16 验证迟到结果只关联原执行尝试，unknown 的补充证据不改写旧事实。task/step/attempt/request 标识及操作矩阵属于满足这些源需求的设计方案，详见 AD-TM-01，未进入实施。

联审补充：AC16 必须覆盖旧步骤观察保留、晚到事实不覆盖当前步骤、事件 n 与最新详情 n+1 区分；AC03 只承诺数据库事务，外部文件已产出而事务失败不允许重放动作或删除产物。用户确认是另一个事实，不能与任务 completed 混为一谈。技术处理见 AD-TM-01，不新增原文之外的产品目标。

- 新增 AC12–16 补回原简报的授权、资源、历史与审计，以及架构要求的结果、错误、等待和恢复。它们是既有需求的展开，不是额外功能。历史查询与用户确认由 TM-S5 承担，TM-S1 不能借此省略写入所需的信息和事务契约。

- AC10 的字段、长度限制、更新主体、脱敏与持久化策略已在 AD-TM-01 子范围定案；实施前仍须生成 OpenSpec 并以 Rust 为唯一协议来源。
- AC11 的内部汇总接口、错误和状态未知语义已在 AD-TM-02 定案，禁止扫描当前 UI 页代替全量事实源。
- v1 库迁移需单独设计、备份与 Change；不得隐式升级。现有拒绝并保留行为不变。
- 核心证据与真实认证、宿主和界面证据分别验收；模拟调用不等于原生闭环。
