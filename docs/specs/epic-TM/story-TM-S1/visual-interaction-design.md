# TM-S1 视觉交互设计

依据产品简报「Task Space 与权限模型」「MVP 主干链路」与补充材料「CUA 与 BUA 的 Task Space」：最新状态展示之外仍需可检查的时间线、结果、产物与审计。本文不代替这些原需求，历史展示须明确归属后再定稿；具体字段、文案和截断属于设计建议。

## 入口与流程

本 Story 无独立窗口，定义 DS-S2 与 AG-S1 消费的状态含义，布局和图标归 DS。进入总览 → 读取授权列表 → 展开任务详情 → 按该任务 sequence 补读事件。切换任务不改变执行状态；列表刷新从首页发现新增，历史仍可查详情。

## 状态与错误反馈

| 数据状态 | 文案建议 | 禁止误导 |
|---|---|---|
| created | 已创建 | 未准入就显示正在执行 |
| running | 执行中 | 无依据的百分比或剩余时间 |
| waiting-for-user | 等待你的操作 | 未归还自动继续 |
| paused | 已暂停 | 把状态记录当作实际停止证据 |
| interrupted | 已中断，需要重新确认 | 重启自动重做 |
| completed | 已完成 | 等同用户已确认产物 |
| failed | 执行失败 | 将 unknown 随意归为失败 |
| cancelled | 已取消 | 刚发取消请求就提前显示 |

加载中不显示空列表；只有成功读取空结果才显示“暂无任务”。读取失败显示“任务状态暂不可用”，保留旧快照时标记非最新，不能推断空闲。身份拒绝不暴露他人任务存在性。

事件只更新对应 task_id，不因另一任务完成而停止全局忙碌。created 的资源等待原因必须来自 TM-S2 真实结果；未提供则只显示已创建。名称/步骤/观察缺失不自动生成，unknown 的动作级表现随元数据契约定案。

## 无障碍与平台验证

- 状态用文字表达，颜色和动画不能作为唯一信息；DS 提供任务行名称、键盘访问和可见焦点。
- 高频事件不抢焦点，不逐条打断用户；等待用户操作和结果变化的通知在 DS 定案。
- 刷新保留 task_id 选中关系，不用行号作身份；进入历史后仍可查详情。
- 核心验证使用固定状态与结构化响应；DS 的 Windows/macOS 原生交互证据独立提交，不以此文档代替视觉验收。

## 待决事项

删除历史与取消任务是不同操作：活动任务先停止确认，不把删除按钮当即时停止。删除确认说明任务记录/Yonder 附件范围，不包含用户文件。删除后本机不可访问不等于远端清理已完成；空间仍未释放时不虚报。附件过期显示“内容已过期，历史记录仍保留”，不得显示任务从未发生。

字节分页可能每页数量不同：界面依据 has_more/游标提供继续加载，不用“少于 100 条”判断已经到底。文字折叠只是展示，不改历史正文；超限提交的错误明确，不能把存储截断误当 UI 折叠。引用无法解析时给出权限/失效/待核实的安全提示，不自动打开事件中的任意路径。

标识在界面中作为稳定关联使用，不向普通用户堆叠技术 ID。客户端收到旧提交回执时只更新该操作的确认，不把最新任务状态退回旧版本。重复点击或断连重投递不能显示第二个执行任务；unknown 后新增证据仍保留此前“待核实”的过程，不悄悄改成从未出错。

联审约束：详情可显示比选中历史事件更晚的状态，但必须标明“当前详情”和历史事件的区别，不把新步骤结果放进旧事件。迟到观察标注其所属步骤，不将当前任务跳回旧步骤。外部产物已生成而记录失败显示“结果待核实”，不提供自动重复执行暗示。

### 本轮补齐的可见信息

详情需要区分“谁发起/当时授权”“当前是否仍允许操作”“使用的资源是否可用”“为什么等待”“如何恢复”。授权撤销不隐藏应保留的本机审计，但 Agent 不能凭历史记录继续读取；外部资源入口失效时显示不可用，不自动打开替代目标。

完成状态与用户确认结果分开显示：任务完成后仍可查看时间线、错误/观察与产物，用户未确认不能标为已验收。此部分由 TM-S5 数据契约与 DS-S2 展示共同实现，不在本 Story 新建独立窗口。

AC10 名称/步骤/观察的缺失、截断和隐私文案，AC11 全局忙碌/未知语义，在 Rust 契约定案后同步。DS-S2 决定具体布局；DS-S3 环绕菜单保持暂缓。

## Agent命名与接管工作引用（2026-09-14用户变更）

AC10展示Agent任务名称与独立说明；历史缺名称明确表达缺失，不伪造来源。AC13目标可用/失效及接管定位阶段由统一快照反馈，失效不自动打开同名窗口；DS按可信状态渲染，用户定位失败可手动处理，Agent不自动恢复。
