# TM-S10 产品需求

## 来源与范围

- 原始需求：产品简报“Task Space 与权限模型”“MVP 主干链路”第 1、9 步要求 Agent 创建任务，并保留结果与产物；TM-S5 AC04～09要求终态、确认和产物分离。
- 后续用户变更（2026-10-16）：Agent 输出不要展示完整内容；交付物不能长期为空；任务分配必须有输入输出契约。
- 架构约束：ARCHITECTURE-SPINE“Agent Gateway”“任务、状态与恢复”“Command、File 与 Document”，以及 Accepted AD-TM-24/25。

## 问题与目标

当前任务分配没有可展示且可冻结的输入/预期输出，完成请求也没有交付摘要；可信 File/Document 输出未进入产物清单，用户无法区分“没有文件型交付物”和“产物接线遗漏”。目标是在不展示完整 Agent 内容的前提下，让每个新任务具有明确契约、每次完成具有有界交付说明，并让真实文件/文档输出自动形成可信产物引用。

## 验收条件

- IO-01：新协议任务创建必须声明有界输入摘要和预期输出；幂等重试内容一致才返回原任务。
- IO-02：Task Space 只显示摘要，不显示内部 description、完整 Agent Payload、截图、输入、路径或完整命令输出。
- OUT-01：任务完成必须携带有界交付摘要，且继续受最新 achieved 目标核验约束；摘要不能把未核验结果变成成功。
- OUT-02：旧任务缺少契约或摘要时明确“未声明”，不得从历史正文补造。
- ART-01：File 新建/替换和 Document 另存成功后产生可信 opaque 产物引用和非空不可变清单。
- ART-02：失败、unknown、读取、回收站、CUA/BUA/Command 无文件产物时不伪造清单；结果由交付摘要表达。
- TX-01：兼容路径同事务保存终态/事件/Outbox/结果；Runtime 路径同一有序事件投影，持久化延迟不阻塞执行。
- COMPAT-01：协议 1.51 及以下保持旧形状；schema 26 安全迁移到 27，旧任务保持缺失而非回填。

## 范围与非目标

本 Story 不存完整任务正文或 Agent 回复，不实现产物内容复制、路径展示、打开产物、云端上传、跨设备同步或通用附件系统。
