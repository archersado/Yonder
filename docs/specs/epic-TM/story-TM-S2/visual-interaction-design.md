# TM-S2 视觉交互设计

## 入口与流程

向任务总览报告真实资源等待原因；unknown 不伪装成功或失败；禁止自动重放。

## 状态与错误反馈

真实 `task.fail` 成功后任务从进行中移至历史，桌宠播放一次既有 failed 动画；读取已有失败任务、请求拒绝或 unknown 不播放。失败详情沿用对应步骤和已观察动作失败事实，不显示 Agent 自报的自由文本原因。减少动态效果只显示同一失败静态姿态，随后恢复真实派生状态。

结果事务不新增窗口。`observed` 仍保持执行展示，等待后续步骤边界决定；`unknown` 显示“结果待核实”并保持占用，不显示完成或自动恢复。旧客户端缺少该字段时沿用任务 running 快照，不能猜测结果。

呈现真实可观察状态；加载、等待、失败和未提供能力不能伪装为完成。无独立界面时由调用方界面或结构化响应承载，不额外建立窗口。

## 无障碍与平台验证

有 UI 的按钮提供名称与可见焦点，支持键盘，减少动态效果遵循系统偏好；无 UI 时保证调用错误稳定可区分。原生交互须各平台独立证据。

## 待决事项

核心准入/start/finish 已存在旧 Change；真实执行器、文件身份与派发前检查尚待设计接线。

## 连续步骤边界反馈

普通步骤推进不改变任务卡片的running状态；事件时间线可显示上一步已观察和下一步骤声明。pending控制或unknown时保持现有“正在停止”或“结果待核实”，不得短暂显示空闲、完成或释放忙碌动画。

## 执行尝试准备反馈

本子范围无新增按钮。事务成功后既有任务面板只显示running和Agent步骤；准备失败保持原状态并向调用宿主返回结构化冲突/不可用，不播放执行成功动画。`prepared`是内部审计事实，不向用户伪装为动作已发生。键盘/无障碍界面不变；真实Driver与平台权限证据后续补齐。
