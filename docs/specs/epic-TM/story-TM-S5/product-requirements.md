# TM-S5 产品需求

## 需求来源

- [产品简报](../../../../_bmad-output/planning-artifacts/briefs/brief-Yonder-2026-09-09/brief.md)「MVP 主干链路」第 9 步、「Task Space 与权限模型」：保留时间线、产物、结果与审计历史。
- [补充材料](../../../../_bmad-output/planning-artifacts/briefs/brief-Yonder-2026-09-09/addendum.md)「CUA 与 BUA 的 Task Space」：持久任务容器和资源引用，资源仍归原应用。
- [架构主干](../../../../_bmad-output/planning-artifacts/architecture/architecture-Yonder-2026-09-09/ARCHITECTURE-SPINE.md)「任务、状态与恢复」「个人上下文」：任务序号、事务、恢复、加密与配额。不引入完整 Event Sourcing。

## 问题与目标

任务结束后，用户需要检查实际做了什么、在哪里接管、为什么失败以及生成了哪些产物。仅保存最新摘要不能回答这些问题。审计记录必须可追溯，不能把外部 Agent 的意图当成已经发生的动作。

## 范围与非目标

包含任务生命周期、步骤/观察、控制与结果确认的历史查询，以及产物引用及其可用性。支持本机用户查看和 Agent 按当前权限查询；执行完成不等于用户确认结果。

不自动录屏或采集输入，不生成语义总结/规划，不实现工作流回放，不复制 ego-lite 页面历史，不接管原应用文件所有权。录制原始数据归 RC，引用访问受原权限和保留策略限制。

## 验收条件

| 编号 | 场景 | 期望 |
|---|---|---|
| TM5-AC01 | 至少两步执行，各自声明意图并 Observe | 能分别检查意图、实际动作/验证事实；第二步不覆盖第一步历史 |
| TM5-AC02 | 用户接管后继续 | 显示请求、确认停止、接管/归还与重新观察的事实，不伪造缺失节点 |
| TM5-AC03 | 同任务结果 unknown | 与明确失败/成功区分，不推断产物正确或自动重试 |
| TM5-AC04 | 任务完成后用户尚未确认，再确认结果 | 执行状态与确认记录分离；重复确认不重复记录，不重新执行任务 |
| TM5-AC05 | 产物移动、删除或发生版本变化 | 显示引用失效/变化，不静默指向另一个文件或把当前内容当原产物 |
| TM5-AC06 | 另一 Agent 查询或权限撤销 | 按当前授权拒绝，不凭历史归属/授权快照绕过 |
| TM5-AC07 | 写事实/状态/Outbox 时注入故障 | 不出现有终态却缺关键事件的部分提交；未提交事件不发布 |
| TM5-AC08 | 历史超过一页、出现保留/删除边界 | 有界读取、稳定序号，缺失范围明确，不伪装为完整历史 |
| TM5-AC09 | 非录制任务完成 | 只有执行所需的获准事实与引用，不自动产生屏幕录制或用户输入轨迹 |

## 首批只读时间线增量（2026-09-18）

来源：产品简报“MVP 主干链路”第 9 步与“Task Space 与权限模型”要求保留并查看时间线；TM5-AC01、AC03、AC08。首批只展示现有正式 `task.events` 已提交的状态、步骤声明和执行观察结果，不新增事件类型、产物、用户确认或录制事实。

- TL-01：任务详情展示按 `sequence` 升序排列的事件，步骤声明明确标为“Agent 声明”，不得冒充已执行。
- TL-02：执行结果区分已观察成功、已观察未达成和 unknown；unknown 原因存在时以用户可读文案展示。
- TL-03：读取失败只影响时间线区域，不清空已经读取的任务详情；空历史、读取失败和未完整加载分别反馈。
- TL-04：首批单页最多 100 条；最后事件序号小于任务当前序号时明确提示仍有记录未加载，不宣称完整。

## 既有事件分页增量（2026-09-18）

来源：TM5-AC08 与 TL-04。时间线存在未加载记录时提供“加载更多时间线”；每次从最后实际显示的 `sequence` 继续，页面按序追加 20 条（协议上限仍为 100）。加载失败、空后续页或序号异常保留已显示历史并明确反馈；切换任务后旧响应不得混入。未来产物/附件等新增 payload 的字节预算仍是独立门禁，本增量只覆盖既有有界事件字段。

该增量不关闭产物身份、用户确认、历史总配额、删除同步或 RC 录制门禁，完整 TM-S5 仍处于设计审阅。

## 待决事项

AC05/06/08/09 增加保留边界：7 天任务附件期限不删除用户产物，未同步/固定/活动引用受保护；附件过期后仍能读获准历史并看见引用失效。删除历史须明确确认其范围，本地与远端清理状态分开，不能宣称未完成的删除已完成。产物集合发布后不可被追加内容悄悄改变旧确认。

2026-09-12 细化 AC05/07/08：引用知道不等于授权、同路径不等于同版本、超限结果不允许漏报产物；分页同时考虑事件条数与响应字节，下一事件未返回时不能越过它推进游标。清单未完整就绪时不得确认完整结果。具体限额属架构设计，不另加产品规模承诺。

本轮走查细化 AC01/03/04/06：重投递同一次操作不追加历史，不同真实观察即使描述相同仍保留；迟到事实保留执行归属，用户确认不重启任务；权限撤销不能经重投递获得旧结果正文。unknown 及其后续证据都可检查，不能事后抹掉未知过程。

本轮细化既有验收：AC01 区分真实两次观察与网络重复投递；AC04 确认引用所检查的结果/产物版本；AC07 区分数据库回滚与外部动作已发生；AC08 不从最新详情重建过去事实。这些场景尚无实施证据。

具体事件字段与大小、保留/删除边界、产物版本识别和确认幂等契约仍待 ADR。以上是源需求验收展开，不表示既有状态事件已满足。密钥研发继续暂停，使用既有安全约束设计，不引入明文后备。

## 人工接管记录与交回（2026-09-14用户变更）

来源：本次用户明确执行中支持人工接管并记录用户行为，作为交回Agent的Observe依据；架构Recording与桌宠/任务恢复约束，Accepted AD-TM-03。仅Agent创建任务，人工接管不创建新任务。

验收映射：TAKE-01显式接管阻止Agent新动作，停止未确认不称已移交；TAKE-02本次手动接管开启可见、可停止的记录，只录user输入，密码/安全界面/排除应用不采；TAKE-03原始时间线不可变并关联原task_id；TAKE-04交回保存证据并执行新鲜Observe，向归属Agent交付轨迹/证据引用及当前状态；TAKE-05交接失败/配额缺口明确反馈、保持暂停，不自动续跑；TAKE-06Agent重新Observe并显式恢复，重新准入后才executing。

TM-S3管接管及停止确认，RC-S1管用户记录/不可变证据，TM-S5管任务时间线引用，TM-S4管交回及显式恢复，AG管归属Agent交接协议，DS-S2展示已有任务接管/记录中/交回。自动输入干预只暂停，不无提示开启Recording；显式接管作为用户手动开始。已有每设备Recording时明确冲突，不覆盖。

UI流程：任务面板“接管”→“正在停止Agent控制/记录中”→停止确认后人工控制；小龙按既有暂停表现并保留独立录制提示。用户可以停止记录，任务仍保持人工接管；交回时如果停止后有未记录操作标注证据缺口，最终Observe仍必须新采集。“交回Agent”不等于立即继续，不用点击桌宠自动恢复任务。

协议/持久化/Driver停止与授权/隐私字段未定稿，相关Story保持设计阶段，不提前实现采集或向外发送用户记录。Windows暂缓、真实双平台证据保留。

## 用户卡片删除首批定稿

# AD-TM-05 用户删除已结束任务

状态：Accepted（MVP本机删除）；日期：2026-09-14。Architecture Impact：architecture-change（协议/持久化）。来源：产品简报Task Space权限模型、架构任务事实源/保留边界、用户要求任务卡片删除；删除语义澄清未获其他选择，采用显式默认清理任务及历史并保留最小防重放标记。不是仅隐藏列表。

用户确认后仅可信LocalUser可删除终态任务；Agent不得删除，活动状态先取消/停止，宿主Busy/Unknown拒绝。UI浏览器原生确认说明任务/历史清理、不能恢复及防重放标记保留；不自动确认真实数据删除。接管/Recording前置不因新增按钮解除。

Rust协议新增task.delete/TaskDelete及DeleteParams（统一身份/能力/deadline、task_id、expected_sequence），复用kind=deleted/task_id响应。此为本机用户控制，不在Agent hello宣称删除能力，不升级Agent1.2。普通query没有真实宿主活动证据时拒绝；正式TaskHost提供自身ActivityState。唯一Rust模型派生Schema/TS。

SQLite4从3同事务加tasks.deleted（默认0）、events.kind（默认transition）。删除同一IMMEDIATE事务：校验原状态/expected_sequence及终态，删除原Outbox/事件，清空task_creations.description；保留task id/owner/state并置deleted=1、sequence加1，插入无正文deleted事件（执行状态不变）及Outbox。其为删除控制事实，不伪装Domain状态迁移。用户明确手动删除历史时处理旧Outbox，新的删除通知仍保留，未来同步消费者必须识别kind=deleted；不自动清理未同步数据。没有轨迹/附件的首批任务仅清理当前已有任务说明/事件；未来附件关联建立前必须更新清理登记协议，不擅自清理文件。

正常list/get/events/running均不可读deleted标记；commit排除deleted。创建幂等遇deleted标记返回-32013任务已删除，不恢复旧描述、不创建新任务。Agent需新幂等键才创建不同任务。终态删除保留最小id/owner/key/state/sequence及删除事件/Outbox，不TTL/自动抹除；不是完整Event Sourcing。

重复删除仅expected_sequence等于删除前或当前时返回既有deleted回执，不增事件；其他旧序号-32011。非终态及Busy/Unknown-32012；权限-32003、不可见-32004；迁移失败全部回滚，错误格式/未知版本拒绝。现有schema2→3迁移后同事务再到4，旧数据保留。无需新依赖/密钥/加密，AD-ST-01保持。

验证：实际文件迁移、四表删除/回滚、序号/身份/活动状态、重复删除与创建不复活；原生卡片删除打开确认后取消，不代替用户确认清理真实任务。实际删除使用独立测试库；macOS截图/日志，Windows仍暂缓，完整TM-S5与接管需求保留。

验收DELETE-01用户终态删除说明与历史，非目标不变；DELETE-02同事务删除事实及Outbox，故障完整回滚；DELETE-03创建重试不复活，重复删除不加事件；DELETE-04用户确认/活动状态/权限门禁不可绕过。来源依次为本次用户变更/原始任务权限模型、架构事实源/事务、原始幂等与历史保留、用户控制与执行停止约束。
