# TM-S6 产品需求

## 需求来源

产品简报「Task Space 与权限模型」「桌宠」及 ARCHITECTURE-SPINE「任务、状态与恢复」；用户补充“后台有任务在执行不能隐藏”，TM-S1 AC11。AC1–3 提供该需求的数据库侧基础，完整收起门禁仍属 TM-S1/TM-S2/DS。

## 问题与目标

当前页面或当前 Agent 没有运行任务，不代表整个宿主没有。提供不受分页和归属筛选影响的全量运行状态查询。

## 范围与非目标

Application 查询与进程内收起预约；不接线桌宠、不提供原生窗口完成保证、不扩展元数据、清理和密钥，不为外部 Agent 新增全局接口。

## 验收条件

- AC1：空库返回 NoRunningTask；超过 100 条任务时仍能发现分页外、其他 Agent 的 running 任务。
- AC2：以已提交当前表为准；完成或显式恢复后重新查询反映变化，不缓存旧结果。
- AC3：读取故障返回 Unknown，绝不回退为 NoRunningTask；恢复可读后重新取实际值。
- AC4：查询不改变任务、sequence、events 或 Outbox；只读取至多一个 running 快照。
- AC5：数据库无 running 时，只要唯一 Admission 尚有占用（包括空资源后台任务），汇总仍为 Busy；只有确认停止并显式释放后才能返回 NoKnownWork。
- AC6：凭证被丢弃不变成空闲；数据库有 running 而无占用时也返回 Busy。
- AC7：宿主尚未提供恢复后的唯一 Admission 时为 Unknown；数据库/占用读取失败且另一来源未确认忙碌时为 Unknown。任一来源确认忙碌时返回 Busy。
- AC8：汇总只观察，不释放、恢复或修改任务；不提供收起许可，不把非原子读取包装成无竞争保证。

- AC9：收起预约与任务准入并发竞争，只允许一方成功；既有占用、重复预约均拒绝收起。
- AC10：预约后核对全量数据库，running 或读取失败拒绝收起并撤销未展示预约；无可信实例为 Unavailable。
- AC11：预约成功直到确认展开前拒绝新任务；丢弃凭证不解除预约。确认展开后显式释放，准入恢复。失败不修改任务或重放动作。
