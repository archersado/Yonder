# TM-S8 视觉交互设计

任务创建后立即在当前 Yonder 的 Task Space 可见。执行中卡片显示能力类型、计划步骤、当前步骤和真实状态；敏感正文与完整参数不显示。

界面必须区分“Codex 正在规划/重新规划”“Jev 正在选择下一动作”“Yonder 正在执行”“等待用户确认”，并显示当前计划片段的步骤进度。不得把 Jev 单候选旁路显示成快脑选择，也不得把等待慢脑显示成执行中。

- CUA：顶部控制条持续显示计划、当前执行步骤和“接管电脑”，终态或显式接管后才收起；发送动作在 Yonder 本机展示目标可读名与正文摘要并确认。
- BUA：Yonder 卡片展示浏览器任务状态和 ego-lite 引用状态，实际浏览交互留在 ego-lite Task Space。
- Office：Yonder 提供源文件和另存目标的本机授权触点、锁冲突/哈希冲突反馈及结果入口。
- Command：Yonder 展示程序、参数、工作目录、环境变量键名、超时和风险提示；用户批准后才进入 running，输出只显示有界摘要。

2026-09-28 统一浮窗修订：上述四类任务只要开始执行，都在与圈选工具条一致的屏幕顶部居中位置显示同一执行浮窗。浮窗固定包含“正在执行”和“规划步骤”两组：当前步骤来自已校验请求或任务事实；存在已验证计划片段时显示至多四项完成/执行中/待执行状态，否则明确显示“未提供后续计划”，不得从自然语言说明猜测步骤。CUA 使用“Yonder 正在控制您的电脑”与“接管电脑”；其余能力使用“Yonder 正在执行任务”，隐藏接管按钮且不暗示桌面受控。任务完成、失败、取消或显式 CUA 接管成功后关闭。

加载、等待批准、执行、Observe、等待慢脑、完成、失败和 unknown 必须可区分；不得用动画或自然语言意图冒充状态事实。

顶部控制条一旦因 `task.plan.execute` 出现，Task Space 的同一任务不得仍显示“已创建”。首动作前交回慢脑时，任务保持“执行中”，阶段文案切换为“等待慢脑重新观察或规划”，直至慢脑继续或提交明确终止状态。
