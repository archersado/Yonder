# TM-S9 产品需求

## 需求来源

- 2026-09-29 用户变更：“数据库应该是作为事后存储，运行时必须是事件驱动的机制”；“SQLite 是当前状态唯一事实源、每步同步事务后推进这个规格约束废除”。
- 既有用户变更：任务存储不要求实时，不能卡住执行，可事后根据内存日志存储；运行时架构应轻量简单。
- 保留约束：unknown 副作用不重试，发送等操作须本机确认，落盘的状态/事件/Outbox 不得相互矛盾。

## 验收映射

| ID | 验收要求 |
|---|---|
| ER-01 | 单一内存事件循环拥有活动任务，SQLite 延迟或失败不阻塞当前 Driver 与 Observe。 |
| ER-02 | Driver 阶段、effect、Observe、当前/完成/待核实步骤即时投影，不等待数据库轮询。 |
| ER-03 | SQLite 后台按连续逻辑序号原子投影快照、事件和 Outbox。 |
| ER-04 | 队列有界；硬限只在下一副作用前暂停并显示持久化积压，不丢结果。 |
| ER-05 | Gateway 对活动任务读 runtime，对历史任务读 SQLite；不得双写。 |
| ER-06 | 重启只恢复完整 checkpoint，遗留 running 转 interrupted，未知副作用不重试。 |
| ER-07 | 发送、支付、删除、安装、提权的确认仍是副作用前置条件。 |
| ER-08 | CUA 首阶段通过后，BUA、Office、Command 复用同一机制。 |

不实现完整 Event Sourcing、跨进程总线、第二数据库或本地 HTTP Server。
