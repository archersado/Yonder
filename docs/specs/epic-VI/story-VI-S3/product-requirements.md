# VI-S3 产品需求

## 问题与目标

Yonder 已能把用户的显式语音转成文字交给 Agent，也能在圈选回复卡展示 Agent 的流式文字，但用户仍必须持续阅读屏幕。用户希望 Yonder 可以把当前 Agent 的回复用本机语音读出，并能随时停止或通过开始新一轮语音输入自然打断。

## 范围与非目标

### 范围

1. 用户可在 Yonder 设置中显式开启或关闭 Agent 语音回复，默认关闭。
2. 只朗读当前已绑定 AgentSession 返回的最终用户可见回复；不朗读 reasoning、工具参数、命令输出、任务事件或顶部执行步骤。
3. 回复文字继续实时显示；达到稳定句界后交给本机 TTS 异步合成，允许并发准备但必须严格按回复序号播放。
4. 用户点击停止、关闭本轮回复卡、切换回复目标或开始新一轮 VI-S1 收音时，立即停止当前播放并丢弃本轮尚未播放的音频。
5. TTS 不可用、超时或单句失败时保留文字回复并给出有界提示，不阻塞 Agent 回复、任务执行或下一轮输入。
6. 原始回复、合成音频和播放振幅仅在本轮内存中短暂存在，终止后清理。
7. Agent 设置提供本地语音试听，使用固定无业务内容文案直接验证同一 TTS Runtime 的可用性、播放与终态，不依赖 Agent 回复链路。

### 非目标

- 不加入唤醒词、后台常开麦克风、声纹、声音克隆或云端 TTS 账号。
- 不让 Yonder 生成回答、改写 Agent 回复或从任务历史补抓正文。
- 不把语音播放状态写成任务状态，不新增聊天历史、音频数据库或长期缓存。
- 不在本 Story 引入 Live2D；嘴型或形象表现只能消费播放振幅等短生命提示，不能改变九种可信任务状态。
- 不保证操作系统尚未安装的语音包自动下载；安装或联网必须由用户明确操作。

## 验收条件

- VI3-01：未显式开启语音回复时不初始化 TTS、不播放声音；开关可随时关闭当前播放。
- VI3-02：同一 `reply_id` 的可朗读文字按严格递增序号进入播放，较晚完成的合成结果不得越过前序句子。
- VI3-03：首个稳定句无需等待完整回复即可开始播放；未闭合 Markdown、代码块、URL、表格标记和不可朗读控制文本不得直接念出。
- VI3-04：开始 VI-S1 收音前先停止播放并释放输出资源；停止播放不取消 Agent turn，也不重新投递输入。
- VI3-05：新回复轮次、断连、失败、超时和用户停止都会使旧轮次迟到结果失效，旧音频不得串入新回复。
- VI3-06：本地 TTS 不可用时显示“本地语音不可用，已保留文字回复”；不得静默调用网络 TTS。
- VI3-07：回复正文、合成音频、声音名称和完整 TTS 错误不得进入 SQLite、事件、Outbox、索引或普通日志。
- VI3-08：播放状态不是任务状态；任务面板、顶部执行浮窗和 CUA/BUA/Office/Command 运行时不会因 TTS 等待而停顿。
- VI3-09：Windows/macOS 分别验证中文长短句、连续多句、单句失败、缺失语音包、离线、停止、新一轮收音打断和进程退出资源释放；单平台通过不能关闭 Story。
- VI3-10：键盘和屏幕阅读器能够操作播放/停止；屏幕阅读器不会与 TTS 对同一正文自动重复朗读。
- VI3-11：显式开启后可通过“试听”单独验证 Yonder 本地播放；UI 显示准备、朗读、完成或不可用，且不生成 Agent 输入、任务或持久化记录。
