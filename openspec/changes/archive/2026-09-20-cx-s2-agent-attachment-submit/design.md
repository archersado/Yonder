# 设计

Agent在握手时除`user_input`外显式声明附件输入能力；不支持附件的会话不能成为圈选提交目标。Application接收最终问题与单个截图字节，执行16 KiB文字、4 MiB附件、允许MIME和deadline校验，再调用同一`AgentInputSink`。Desktop Hub在交互开始时冻结目标会话，生成稳定输入/附件标识并交给该会话的返回通道。

Rust协议新增附件开始、分块与完成消息；开始声明会话、MIME、原始字节数、SHA-256和deadline，分块保持编码后帧不超过64 KiB，完成确认后`agent.input`引用附件标识。可靠有序传输承载分块，接收端完成总量与哈希校验后确认；Yonder收到拒绝、unknown、超时或断连均关闭本次提交并清理本机截图。不得发送本机路径、扩大现有帧上限或建立第二连接。

确认卡复用现有窗口，增加可访问的问题输入和“发送”。提交中禁用重复操作；accepted后关闭并清零，拒绝/unknown保持错误说明但清除已提交附件，用户若要重试必须重新圈选，避免自动重复副作用。没有兼容Agent时明确显示“当前Agent不支持截图提问”。

首批验证使用受控本地Agent，不保存真实截图：协议合约覆盖能力协商、帧/总量、乱序和错误；集成覆盖确认卡→附件完成→`agent.input`引用→accepted，以及拒绝、unknown、断连和无能力会话。SQLite、事件、Outbox、日志和文件系统差分不得出现问题正文、图片、base64或哈希。
