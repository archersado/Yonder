# 设计

macOS Adapter在AppKit主线程注册屏幕参数通知，并复用既有共享清场函数。观察者只在圈选层或确认卡可见期间存在；清场、发送、打开失败和原生关闭都会注销它。Application仍是会话、语音和附件清场的唯一所有者。

分辨率变化可能同时触发原生`CloseRequested`或应用切换通知；这些路径与屏幕通知最终进入同一清场不变量，允许实际清理原因竞争，但不得残留截图、选区、笔画或语音。

验证使用公开`CGDisplaySetDisplayMode`临时切换主显示器模式并立即恢复：确认卡必须关闭，隐藏窗口标题必须记录清理原因和零资源状态，且不保存截图、问题或语音正文。

Windows Adapter使用独立短生命消息线程和message-only HWND。观察器只在选择层/确认卡会话打开后注册，`WM_DISPLAYCHANGE`首次到达即冻结重复回调并调用同一共享清场；该消息覆盖显示拓扑、分辨率和显示器接拔变化，同时避免通用`WM_DEVICECHANGE`因无关USB设备变化误触发。清场向该HWND投递`WM_CLOSE`、等待线程退出并注销窗口类。它不轮询DisplayConfig、不监听键鼠、不读取窗口内容，也不改变Application的会话所有权。

Windows先用原生消息窗口单元测试验证注册、通知、单次回调、停止和重复启动；真实显示模式变化、物理断开、副屏与负坐标仍需实机证据。合成消息只证明Adapter接线，不能冒充真实硬件通知。
