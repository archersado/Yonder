# task-control Delta Specification

## MODIFIED Requirements

### Requirement: CUA 人工接管必须来自显式本机入口

系统在真实 CUA 执行区间必须显示与圈选工具条同屏、同顶部居中位置和同视觉样式的控制条；普通 HID 输入不得自动暂停。只有控制条“接管电脑”按钮可以登记本轮接管，已派发动作完成并 Observe 后才可提交暂停与定位。

控制条 MUST 绑定已经开始 CUA 的任务生命周期，而不是单次动作请求。单个动作返回、步骤间 Observe、慢脑下一步决策等待和普通用户输入后 MUST 保持可见；只有任务完成、失败、取消、显式接管成功或宿主确认执行会话终止后才能隐藏。

#### Scenario: 普通输入不停止

- **WHEN** CUA 动作执行期间出现物理鼠标或键盘输入
- **THEN** Worker 继续执行且任务不产生新的 `unknown/user-input`

#### Scenario: 显式点击接管

- **WHEN** 用户在当前 CUA 控制卡点击“接管电脑”
- **THEN** 系统冻结后续动作、等待当前动作 Observe，并以最新任务 sequence 提交既有 takeover 控制

#### Scenario: 步骤间点击接管

- **WHEN** 控制卡仍显示且 CUA 处于动作响应之后、下一条 Agent 请求之前
- **THEN** 宿主立即在任务串行边界提交 takeover，不等待新的 Gateway 帧，投影刷新期间按钮保持禁用

#### Scenario: 控制卡位置

- **WHEN** CUA 在多显示器环境开始执行
- **THEN** 控制条使用圈选交互相同的 pet 当前显示器与 work area，在该工作区顶部 16 逻辑像素处横向居中显示且不遮挡条外区域

#### Scenario: 单步返回后继续显示

- **WHEN** CUA 任务的一个动作已返回并完成 Observe，但任务仍为运行态
- **THEN** 控制条保持可见并等待下一步骤，不因 RPC 响应或普通键鼠输入清理

#### Scenario: 任务终态后收起

- **WHEN** 当前 CUA 任务成功完成、失败或取消，或者显式接管已成功提交
- **THEN** 宿主清理对应 task_id 的活动控制状态并隐藏控制条

#### Scenario: 快慢脑与执行分层可见

- **WHEN** 慢脑计划片段进入Jev选择并派发真实CUA动作
- **THEN** 控制条分别显示有界计划步骤、快脑候选选择状态和当前Driver步骤，且不包含思维链、原始响应、参数或正文

#### Scenario: 首次事件早于页面监听器

- **WHEN** 宿主已发布活动投影并显示窗口，而WebView脚本稍后才完成加载
- **THEN** 页面主动读取当前投影并恢复文案、步骤与接管按钮，不显示空白卡片

#### Scenario: 步骤成功图标只来自已提交结果

- **WHEN** 当前步骤开始执行、返回未知或仅取得无法核实语义的截图
- **THEN** 控制条显示当前执行或待核实，不得把该步骤或前序步骤推断为成功
- **AND WHEN** Application 已接受有效动作结果并提交步骤边界
- **THEN** 对应步骤显示带“已完成”可访问语义的成功图标，下一步骤才显示执行中
