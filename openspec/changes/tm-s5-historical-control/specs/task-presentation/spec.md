# 任务控制历史

## ADDED Requirements

### Requirement: 已提交控制阶段按原序号可检查

Yonder MUST 在已授权的任务历史中分别表示已提交的控制请求和步骤边界停止，不得从当前控制阶段反推旧事件或把请求表示为已接管。

#### Scenario: 请求后停止

- **WHEN** 一个控制请求先以 pending 登记、之后在步骤边界确认停止
- **THEN** 历史分别在对应序号显示请求登记与停止确认，且二者关联同一控制身份和执行尝试

#### Scenario: 直接停止

- **WHEN** 控制请求与确认停止在同一事务和序号发生
- **THEN** 该序号只显示已停止，不伪造先前 pending 阶段

### Requirement: 新控制字段保持协议兼容和授权边界

Yonder MUST 只对协商协议 1.22 的授权会话输出 `control_event`，并继续执行既有历史连续性、分页与编码预算限制。

#### Scenario: 旧协议或越权读取

- **WHEN** 协商 1.21 的客户端读取同一历史，或非归属 Agent 请求读取
- **THEN** 旧客户端不收到新增字段，越权请求不泄露控制事实
