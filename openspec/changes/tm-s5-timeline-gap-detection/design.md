# 设计

Application 在现有身份和读取权限通过后取得任务当前序号及最多 `limit` 条已提交事件。历史记录先检查原始序号，再进行版本投影与字节分页：第一条须为 `after_sequence + 1`，之后逐条加一。读取条数少于 `limit` 且末尾序号仍小于已读取的任务当前序号时，判定尾部缺口；空页以请求游标作为末尾。若当前快照后有并发提交，允许页中出现更高的连续事件，不误报缺口。游标已到任务序号且没有更新事件时返回正常空页。

缺口返回独立 RPC 错误码和中文提示“任务历史不完整”，不包含任务正文或其他任务信息。已加载的 Task Space 时间线沿用局部失败处理，保留旧列表，用户可刷新；不把缺口处之后的记录追加。旧协议投影使用同一原始序号检查。

验证通过独立 SQLite 测试库注入首项/中间/尾部缺口，并检查错误与数据库只读性质；正常分页、空页和越权仍保留。
