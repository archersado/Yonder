# 独立 Verification Goal：快慢脑与纯慢脑效果对照（macOS）

状态：FAIL，首轮预跑已发现快脑选择阻断，返回实施阶段。关联 TM8-08、TM8-09、TM8-13 与本 Change 的“同任务配对证据”要求。

## 样本与模式

- 三类可复位、无对外副作用 CUA：确定性本地编辑、动态应用内检索、元素缺失后的 Observe/恢复。
- 每类先跑 3 对预跑；测量与产品缺陷关闭后，另跑至少 10 对正式样本。
- `fast-slow`：Codex 一次提交完整片段，至少一个多候选槽位由真实 Jev 选择。
- `slow-only`：同一 Codex 每次 Observe 后经产品 Gateway 提交下一单步。
- 每对初态、目标、成功谓词与超时一致；顺序逐对交替。

## 通过门槛

- 每个正式 trial 都能由 `task.get/task.events`追溯到真实 MCP、Gateway、Driver、Observe、目标核验与终态；无直接 Driver/SQLite/测试宿主推进。
- 完成率分母包含超时、`unknown`、错误目标、人工修正和未达目标；成功必须为最新 Observation 绑定的 achieved 核验及 completed 终态。
- 报告每种模式的完成数/总数、Wilson 95% 区间、主动耗时中位数/P95、慢脑调用、handback、动作和 unknown；另报墙钟耗时与用户等待。
- 只有完成率不下降，且双成功配对的主动耗时比具有一致方向时，才可记录“快慢脑更快”的阶段结论；样本不足时只报告观察结果。

- 正式 Yonder GUI、安装包内 MCP、同一 `codex-cli` 与 TextEdit 无外发本地编辑目标。
- 有完整计时的一对：快慢脑在启动和有效 Observe 后于 12,602ms 交回，目标未达成；纯慢脑执行 3 个动作，于 41,321ms 达成目标并完成目标核验。原始脱敏 manifest 与汇总器位于本 Change。

代码审查定位到当前 `JevDecisionRequest` 只含 `step_id` 和候选声明，不含槽位可读目标或新鲜 Observe 的真实事实；`select` 还把所有计划候选固定标为 `dispatchable=true`、`parameter_complete=true`。远端模型只能依据候选自报条件和不透明引用判断，等价候选也连续低置信/交回。这不满足 TM8-08 的“基于已验证计划与最新 Observe 判断”，须返回 EX-S2/TM-S9 修复后重跑。
