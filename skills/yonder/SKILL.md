# Yonder

把一个用户目标作为一个 Yonder 任务完成。Yonder 是任务、执行准入、Observe、控制和状态的唯一产品入口；本 Skill 只负责编排已发布工具，不实现第二套 Planner、快脑、Driver 或任务状态。

## 开始前

1. 检查当前会话是否发现 Yonder MCP 工具。至少需要 `task_create`、`task_get`、`task_events` 和目标能力的工具。
2. 以工具发现结果为准，不根据本文猜测参数。缺少目标能力时明确报告“当前 Yonder 尚不支持该能力”，不要改用通用 shell、其他浏览器、直接文件写入或 Computer Use 冒充完成。
3. 为整个用户目标生成一个稳定的 `idempotency_key`、简短任务名和不含敏感正文的说明，只调用一次 `task_create`。重试创建时复用同一个幂等键。
4. 保存返回的 `task_id` 和最新 `sequence`。每次变更都使用最新序号；发生 CAS 冲突时先 `task_get` 和 `task_events`，再依据新鲜事实决定下一步。

## 选择执行模块

- 网页、Web 应用或浏览器标签页：读取 [浏览器任务](references/browser.md)。
- 原生桌面应用、键鼠或 UI 自动化：读取 [桌面任务](references/computer.md)。
- DOCX、XLSX、PPTX：读取 [文档任务](references/document.md)。
- 本地程序或命令行：读取 [命令任务](references/command.md)。
- 复合目标仍只使用一个 Yonder 任务；按实际边界依次读取所需模块，不为每种能力另建任务。

## 生命周期

1. 创建任务后读取快照，确认任务归属、状态和序号。
2. 在执行前形成覆盖当前有界子目标的计划，不把同一明确目标拆成反复的单动作慢脑调用。
3. 调用对应 Gateway 工具。任务步骤、计划、执行、等待、交回和终态都必须来自 Yonder 返回事实，不用自然语言伪造状态。
4. 每个有效动作后使用 Yonder 的 Observe 结果。工具已经组合 Observe 时不要再制造重复成功事实。
5. 需要登录、授权、选择文件、确认发送或其他用户动作时，在安全步骤边界使用现有等待/交接入口，然后停止 Agent 操作。
6. 收到交回、Observe 失败、目标丢失、用户接管、`unknown` 或断连时，先读取 `task_get` 与 `task_events`。不得自动重试结果待核实的副作用。
7. 只有 Yonder 事实证明目标完成且处于允许的步骤边界时才调用 `task_complete`；已观察失败使用 `task_fail`。取消和接管使用当前序号及对应控制工具。

## 计划片段原则

对支持 `task_plan_submit` / `task_plan_execute` 的 CUA 目标：

- 慢脑一次提交一个完整的受限计划片段。片段覆盖当前可预见的连续步骤，通常为 2–10 个槽位；不要默认每次只规划一个动作。
- 一个槽位表达一个用户可理解的步骤；同槽位候选是完成同一语义步骤的替代动作，不是后续步骤列表。
- 候选动作名与参数只从当前 Yonder 工具 Schema 和 CUA Runtime 能力取得。不要在 Skill 中维护动作枚举。
- 优先使用可验证元素或原生语义定位；只有元素不存在、不唯一或不可操作时，才在同一计划片段中提供视觉定位候选。不要每一步都截图。
- 为每个候选填写真实前置条件和预期 Observe。Jev 只在已验证片段内选择候选并连续推进；正常的逐步 Observe 不触发慢脑重规划。
- 仅在片段外语义变化、无可用候选、预期条件不满足、结果 `unknown`、预算耗尽或需要新确认时交回慢脑。交回后读取新鲜任务与事件，再提交新版本片段。
- 发送、支付、删除、安装、提权等副作用必须在实际动作前取得 Yonder 接受的一次性确认引用；没有引用就等待用户，不得把确认写成布尔值或自然语言假设。

## 数据边界

不要读取 Yonder SQLite、直接连接 Local Socket、调用 Driver Worker 或修改 Runtime 配置。不要在日志或答复中输出正文、截图、输入、完整命令输出、完整 Agent Payload、凭据或一次性确认内容。只保留完成任务所需的有界摘要、引用和结构化结果。

完成时简要报告任务终态和必要产物引用；若未完成，报告 Yonder 的结构化状态、最小原因以及下一步，不把“已请求”表述成“已成功”。
